Лекція 8: effort, бюджет задачі та збережені роздуми

Спрощена версія. Повна: ../8-effort-task-budgets-preserved-thinking-sandbox-hooks.md. Sandbox і рідкісні події hooks з цієї лекції прибрано: в іспиті їх немає.

Що з цього питають на іспиті

Як керувати витратами (effort, бюджет) і чого не можна міняти в розмові, щоб не зламати роздуми й кеш.

Головна ідея

Не кожна задача потребує максимуму зусиль. Effort і бюджет дають платити лише за потрібну глибину. А історію розмови можна лише доповнювати, не переписуючи.

Частина 1. Effort

Effort це параметр output_config.effort: скільки зусиль модель вкладає у відповідь. Він впливає на всі токени: текст, виклики інструментів і роздуми.

Рівень Коли
low Прості задачі, швидкість, субагенти
medium Баланс швидкості й якості
high Складні задачі
xhigh Довгі агентні й кодові задачі
max Найглибші роздуми без обмежень

Що знати:

  • За замовчуванням high, а на Opus 5.5 і Haiku 5.5 medium.
  • Effort це сигнал, а не жорсткий бюджет. Жорстка стеля це max_tokens.
  • adaptive не рівень effort, а режим thinking.
  • Нижчий effort означає менше й коротші виклики інструментів.
  • Щоб модель думала менше, спершу знизь effort, а не проси про це в промпті.

Як змінити effort посеред розмови

Спосіб Що з кешем
Нове верхнє значення effort у наступному запиті Скидає кеш
Per-message effort (повідомлення role: "system" з output_config.effort, beta) Зберігає кеш

Тож у розмові з кешем тримай верхній effort незмінним або бери per-message effort.

Частина 2. Task budget

Task budget це дорадчий бюджет токенів на весь цикл агента, тобто на багато запитів. Модель бачить зворотний відлік і сама планує роботу, щоб закінчити акуратно.

Правила:

  • налаштування output_config.task_budget з type: "tokens" і total, потрібен beta-заголовок;
  • мінімум 20 000 токенів, менше дає 400;
  • бюджет дорадчий: модель може трохи вийти за нього, а жорстка стеля лишається max_tokens;
  • рахується те, що модель бачить (роздуми, виклики, результати, текст), а не те, що ти знову надсилаєш в історії;
  • у Claude Code не підтримується;
  • надто малий бюджет може виглядати як відмова: модель рано зупиняється.

Поле remaining потрібне, лише коли твій код сам ущільнює історію. Не зменшуй його на кожному запиті: це скидає кеш.

Частина 3. Збережені роздуми (Claude 5.1+)

Коли ти повертаєш блок thinking, API перевіряє підпис: чи модель може його прочитати і чи все перед ним лишилось незмінним.

Правило: працюй append-only, тобто лише додавай повідомлення в кінець.

Можна Ламає блоки
Додати повідомлення в кінець Змінити system
Змінити effort, max_tokens, tool_choice Додати, прибрати чи змінити інструмент
Додати чи прибрати cache_control Змінити чи видалити раніші повідомлення
Серверне ущільнення чи context editing Скоротити раніший tool_result

Що робити замість правок: зміни system повідомленням role: "system" у кінці, зміни інструментів блоками tool_addition і tool_removal, зміну effort через per-message effort.

Що робить API при розбіжності (thinking.block_binding.prefix_mismatch_behavior):

  • "error": 400. Для тестів.
  • "drop_block": відкидає невдалий блок і всі наступні. Це латка, бо якість може впасти.

У відповіді є масив input_transformations зі списком відкинутих блоків. Логуй його на кожному ході.

Частина 4. Ущільнення: два доповнення

  • Keep-tail: останні ходи лишаються дослівно після підсумку. Ріж там, де не лишилось відкритих викликів інструментів, інакше API відхилить запит.
  • Фонове ущільнення: підсумок готується, поки розмова триває. Коли блок прийшов, відкинь рівно ті повідомлення, які надсилав на підсумок, а пізніші ходи лиши після блоку.

Умова для обох: system і tools не змінюються, інакше роздуми в залишених ходах стануть недійсними.

Що запам'ятати на іспит

  1. Effort за замовчуванням high, на Opus 5.5 і Haiku 5.5 medium. Це сигнал, жорстка стеля max_tokens.
  2. Зміна верхнього effort скидає кеш, per-message effort ні.
  3. Task budget дорадчий, мінімум 20 000, у Claude Code не працює.
  4. Збережені роздуми: лише append-only. Зміна system чи tools ламає блоки.
  5. input_transformations логуй на кожному ході.
