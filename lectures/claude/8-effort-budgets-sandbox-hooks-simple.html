Лекція 8: effort, бюджет завдання, збережені роздуми, sandbox і hooks

Спрощена версія. Повна: ../8-effort-task-budgets-preserved-thinking-sandbox-hooks.md. Рідкісні події hooks і довгі списки моделей лишились лише там.

Головна ідея

Це лекція про керування витратами (effort, бюджет), про те, що не можна ламати в розмові (збережені роздуми), і про межі безпеки (sandbox, hooks).

Навіщо це так задумано

Не кожне завдання потребує максимуму зусиль, тому effort і бюджети дають платити лише за потрібну глибину, а sandbox і hooks страхують від небезпечних дій.

Частина 1. Effort

Effort це параметр output_config.effort: скільки зусиль вкладає модель. Він діє на всі токени: текст, виклики інструментів і роздуми.

Рівень Коли
low Прості завдання, швидкість, субагенти
medium Баланс швидкості й якості
high Складні завдання
xhigh Довгі агентні й кодові завдання
max Найглибше мислення без обмежень

Що знати:

  • За замовчуванням high, а на Opus 5.5 і Haiku 5.5 medium.
  • Effort це сигнал, а не жорсткий бюджет. Жорстка стеля це max_tokens.
  • adaptive не є рівнем effort: це режим thinking.
  • Нижчий effort означає менше й коротші виклики інструментів.
  • Щоб думати менше, спершу знижуйте effort, а не просіть у промпті.

Зміна effort у розмові

Спосіб Що з кешем
Нове верхнє значення effort у наступному запиті Скидає кеш
Per-message effort (повідомлення role: "system" з output_config.effort, beta) Зберігає кеш

Тому в розмові з кешем тримайте верхній effort сталим або використовуйте per-message effort.

Частина 2. Task budget (бюджет завдання)

Task budget це дорадчий бюджет токенів на весь цикл агента (багато запитів). Модель бачить зворотний відлік і сама планує роботу, щоб закінчити акуратно.

Правила:

  • налаштування output_config.task_budget з type: "tokens" і total; потрібен beta-заголовок;
  • мінімум 20 000 токенів, менше дає 400;
  • він дорадчий: модель може трохи перевищити. Жорстка стеля лишається max_tokens;
  • рахується те, що модель бачить (роздуми, виклики, результати, текст), а не те, що ви повторно надсилаєте в історії;
  • не підтримується в Claude Code;
  • занадто малий бюджет може призвести до поведінки, схожої на відмову: модель рано зупиняється.

Поле remaining потрібне лише коли ваш код сам ущільнює історію. Не зменшуйте його на кожному запиті: це скидає кеш.

Частина 3. Збережені роздуми (Claude 5.1+)

Коли ви повертаєте блок thinking, API перевіряє його підпис: чи може модель його прочитати і чи все перед ним лишилось незмінним.

Правило: працюйте append-only, тобто лише додавайте повідомлення в кінець.

Дозволено Ламає блоки
Додати повідомлення в кінець Змінити system
Змінити effort, max_tokens, tool_choice Додати, прибрати чи змінити інструмент
Додати чи прибрати cache_control Змінити чи видалити раніші повідомлення
Серверне ущільнення чи context editing Скоротити раніший tool_result

Що робити замість правок: зміни system через повідомлення role: "system" в кінці, зміни інструментів через блоки tool_addition і tool_removal, зміну effort через per-message effort.

Режим невідповідності (thinking.block_binding.prefix_mismatch_behavior):

  • "error": 400. Для тестів.
  • "drop_block": відкидає невдалий і всі наступні блоки. Лише заплата, бо може змінити якість.

У відповіді є масив input_transformations зі списком відкинутих блоків. Логуйте його на кожному ході.

Частина 4. Ущільнення: два додатки

  • Keep-tail: останні ходи лишаються дослівно після підсумку. Розріз має бути там, де жоден виклик інструмента не лишився відкритим, інакше API відхилить запит.
  • Фонове ущільнення: запит підсумку йде, поки розмова триває. Коли блок прийшов, відкиньте рівно ті повідомлення, що надсилали, а пізніші ходи лишіть після блока.

Умова для обох: system і tools не змінюються, інакше роздуми в залишених ходах стають недійсними.

Частина 5. Sandbox у Claude Code

Sandbox це межа рівня операційної системи навколо shell-команд (Bash, PowerShell, Monitor) і їхніх дочірніх процесів.

Що знати:

  • Вимкнений за замовчуванням. Вмикається /sandbox чи sandbox.enabled: true.
  • Працює на macOS, Linux і WSL2. На звичайному Windows команди йдуть без sandbox.
  • Поза ним: файлові інструменти Claude (Read, Edit, Write), MCP-сервери й hooks. Їх захищають правила дозволів.
  • За замовчуванням читання відкрите майже всюди, зокрема ~/.ssh і ~/.aws/credentials. Додайте denyRead, якщо це проблема.
  • Мережа йде через проксі зі списком дозволених доменів. Проксі не розшифровує TLS, тому можливий обхід (domain fronting): широкі домени на кшталт github.com ризиковані.
  • Змінні середовища (з секретами) успадковуються.

Два режими sandbox:

Режим Що
Auto-allow Sandbox-команди без запиту (не плутайте з auto mode)
Regular Кожна команда за звичайним потоком дозволів

Як вимкнути команду з sandbox: excludedCommands (виконується без обмежень, ризиковано) і повторна спроба dangerouslyDisableSandbox (вимикається allowUnsandboxedCommands: false).

Для організацій: у managed settings sandbox.enabled, failIfUnavailable: true, allowUnsandboxedCommands: false.

Sandbox і дозволи доповнюють одне одного. Правила перевіряють виклик до виконання, а sandbox тримається навіть тоді, коли дозволена команда робить більше, ніж натякає ім'я.

Частина 6. Hooks: що ще треба знати

  • PreToolUse не спрацьовує на @file у промпті. Блокуйте шляхи через Read deny.
  • updatedInput замінює весь вхід інструмента.
  • PostToolUse не може скасувати дію: інструмент уже виконано.
  • PermissionRequest: забороняти можна лише command hook із decision.behavior: "deny". Prompt hook із ok: false тут не діє.
  • PreCompact: exit 2 чи decision: "block" блокує ущільнення.
  • Stop hook: до 8 продовжень поспіль, перевіряйте stop_hook_active. Є також нейтральніший additionalContext.
  • Async hook ("async": true, лише command) нічого не блокує, результат приходить на наступному ході.
  • Prompt hook повертає {"ok": true|false, "reason"}; для Stop ok: false змушує Claude працювати далі, для PreToolUse забороняє виклик.
  • Безпека: command hooks виконуються з усіма правами вашого користувача. У режимі -p (без діалогу довіри) hooks із .claude/settings.json репозиторію запускаються без перевірки довіри. Перед скриптуванням claude -p над чужим репозиторієм перегляньте його .claude/.

Що запам'ятати на іспит

  1. Effort за замовчуванням high, на Opus 5.5 і Haiku 5.5 medium. Це сигнал, жорстка стеля max_tokens.
  2. Зміна верхнього effort скидає кеш, per-message effort ні.
  3. Task budget: дорадчий, мінімум 20 000, не в Claude Code.
  4. Збережені роздуми: лише append-only. Зміна system чи tools ламає блоки.
  5. input_transformations логуйте щоходу.
  6. Sandbox вимкнений за замовчуванням, охоплює лише shell-команди, читання відкрите.
  7. PreToolUse не бачить @file. PostToolUse нічого не скасує.
  8. Async hook не блокує. Prompt hook на PermissionRequest не діє.
  9. У режимі -p hooks із репозиторію запускаються без діалогу довіри.
