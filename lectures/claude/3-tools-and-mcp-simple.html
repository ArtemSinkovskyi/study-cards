Лекція 3: як описувати інструменти і що таке MCP

Спрощена версія. Повна: ../3-define-tools-handle-results-mcp-connector.md. Рідкісні деталі (повні списки моделей, коди помилок) лишились там. Погляд курсу на дизайн інструментів у лекції 10.

Що з цього питають на іспиті

Від чого залежить, чи обере модель правильний інструмент. Який tool_choice узяти в конкретній ситуації. Що вміє і чого не вміє MCP connector.

Головна ідея

Модель обирає інструмент лише за його описом. Опис це все, що вона про інструмент знає, тому він важливіший за все інше.

Крок 1. Як описати інструмент

Інструмент має чотири поля: name, description, input_schema і, за бажанням, input_examples.

Для моделі це як OpenAPI-контракт: коду вона не бачить, лише контракт.

В описі має бути:

  • що робить інструмент;
  • коли його брати і коли ні;
  • що означає кожен параметр;
  • чого він не повертає.

Документація радить щонайменше 3-4 речення. Добрий приклад: «Повертає поточну ціну акції за тікером з NYSE чи NASDAQ, у доларах. Використовуй, коли питають про поточну ціну. Іншої інформації про компанію не повертає.» Поганий: «Дає ціну акції».

Крок 2. Ще чотири поради

  • Скільки інструментів. Документація радить один pr з параметром action замість create_pr, review_pr, merge_pr. Курс до іспиту (лекція 10) ставить акцент інакше: різні дії розбивати (search_flights, book_flight замість handle_travel(action)), а об'єднувати лише кроки, що завжди йдуть разом. В одному вони згодні: ні десятків дрібних інструментів, ні одного «на все». На іспиті тримайся версії курсу.
  • Префікси в назвах, коли інструментів багато: github_list_prs, slack_send_message.
  • Повертай лише корисні поля. Довгі результати з'їдають контекст.
  • input_examples допомагають зі складним входом. Кожен приклад має відповідати схемі, інакше 400.

Крок 3. Як змусити модель обрати інструмент: tool_choice

таблицю можна гортати вбік →
Значення Що робить Коли брати
auto Модель вирішує сама (за замовчуванням, коли є інструменти) Звичайний асистент
any Мусить викликати якийсь інструмент Структурована відповідь
tool Мусить викликати названий Обов'язковий крок: завжди save_report
none Не викликає (за замовчуванням, коли інструментів немає) Відповідь лише текстом

Що варто знати:

  1. За курсом до іспиту any і tool не поєднуються з extended thinking.
  2. З документації: на Opus 5.5, Sonnet 5.5, Fable 5.1 і Mythos 5.1 значення any і tool дають 400. Там бери auto разом зі strict.
  3. З any і tool модель не пише пояснення перед викликом.
  4. Зміна tool_choice посеред розмови скидає кеш повідомлень (інструменти й system лишаються в кеші).

Крок 4. Як повертати результат

Три жорсткі правила, за порушення буде 400:

  1. tool_result іде одразу після повідомлення з tool_use, між ними нічого.
  2. У user-повідомленні блоки tool_result стоять першими, текст після них.
  3. Усі результати одного ходу йдуть в одному повідомленні (лекція 2).

Типова помилка: «tool_use ids were found without tool_result blocks immediately after».

Крок 5. Помилки в інструментах

  • Інструмент упав: tool_result з is_error: true і зрозумілим текстом. Не «failed», а «Rate limit exceeded. Retry after 60 seconds».
  • Модель викликала інструмент без обов'язкового параметра: зазвичай вона пробує ще 2-3 рази з виправленнями. Краще покращити опис.
  • Щоб такого не було взагалі, став strict: true: вхід гарантовано відповідає схемі, а назва інструмента завжди правильна.

Крок 6. Безпека

Результати інструментів часто містять чужий вміст: сторінки, листи, відповіді сторонніх API. Хтось може сховати там інструкцію «ігноруй усе й зроби ось що». Це indirect prompt injection.

Правило: тримай такий вміст усередині tool_result, а не в системному промпті чи звичайному тексті користувача.

І ще: схеми інструментів кешуються до 24 годин, тож не клади в схему персональних даних (у назви властивостей, enum, const, pattern).

Крок 7. Що таке MCP

MCP (Model Context Protocol) це протокол, через який модель підключається до зовнішніх систем. Один MCP-сервер дає набір інструментів.

MCP connector це функція Messages API, яка підключає віддалені MCP-сервери без твого власного MCP-клієнта (beta).

Обмеження, про які питають:

  • лише виклики інструментів (без ресурсів і промптів);
  • сервер має бути на публічному HTTPS (Streamable HTTP чи SSE);
  • локальний STDIO-сервер не підключити.

Для приватної мережі (скажімо, Loki чи Prometheus усередині) connector не підходить: потрібне власне MCP-з'єднання. SDK має для цього допоміжні функції (client-side helpers).

Крок 8. Як налаштувати MCP connector

У запиті два шматки:

  1. mcp_servers: список серверів із полями type (url), url, name, authorization_token.
  2. mcp_toolset у масиві tools: що саме вмикати з цього сервера.

Кожен сервер має рівно один mcp_toolset.

Як зробити асистента лише для читання:

  • Denylist: вимкни небезпечні інструменти (configs з enabled: false).
  • Allowlist: default_config.enabled: false і ввімкни тільки потрібні.

OAuth-токен ти отримуєш сам, передаєш в authorization_token і сам же оновлюєш.

У відповіді приходять блоки mcp_tool_use і mcp_tool_result.

Крок 9. Tool runner

Замість власного циклу (лекція 2) SDK може вести цикл сам: ти описуєш інструменти як функції, а runner їх виконує й веде розмову. Помилки він теж загортає в is_error.

Свій цикл потрібен, коли треба схвалення людини, власне логування або умовне виконання.

Що запам'ятати на іспит

  1. Опис інструмента найважливіший: що робить, коли брати й коли ні, параметри.
  2. tool для обов'язкового кроку, any для структурованої відповіді, auto не гарантує виклику.
  3. tool_result одразу після tool_use і перед текстом.
  4. Помилка: is_error: true і зрозумілий текст. strict: true прибирає неправильні виклики.
  5. Результати інструментів недовірені: тримай їх у tool_result.
  6. MCP connector: лише інструменти, лише публічний HTTPS, без STDIO.

Перевір себе

  1. Що модель знає про твій інструмент?
  2. Агент мусить завжди викликати save_report. Який tool_choice?
  3. Де в user-повідомленні стоять tool_result?
  4. Чи можна через connector підключити локальний STDIO-сервер?
  5. Як зробити MCP-асистента лише для читання?
  6. Що гарантує strict: true?
Відповіді
  1. Лише опис і схему параметрів.
  2. {"type": "tool", "name": "save_report"}.
  3. Першими, текст після них.
  4. Ні, лише публічний HTTPS.
  5. Denylist небезпечних або allowlist потрібних інструментів у mcp_toolset.
  6. Вхід відповідає input_schema, а назва інструмента правильна.
