Lecture 5: Claude Code, the basics

Simplified version. The full lecture exists in Ukrainian only. Only what the exam domains cover is kept here. The exam-course view of Claude Code configuration is in lecture 11.

What the exam asks about this

What only advises the model and what guarantees. How CLAUDE.md levels work. Where to put a rule for part of the code. What skills, subagents and plan mode give you.

The main idea

Some things advise the model; others guarantee. The exam keeps asking about exactly this difference.

Only advises Guarantees
CLAUDE.md, rules, skills, the prompt Hooks (PreToolUse), a check in code

CLAUDE.md is like a README: people read it, nobody is forced to follow it. A hook is like a Spring Security filter: it cannot be bypassed.

So the answer to "how do I guarantee X" is never "write it in CLAUDE.md".

Step 1. CLAUDE.md

The instruction file Claude reads at the start of every session. It is context, not an enforced rule.

How to write it:

  • up to 200 lines, because a bloated file is followed less well;
  • concrete: "Use 2-space indentation", not "format nicely";
  • only what Claude cannot guess: pitfalls, departures from defaults, the reason behind a rule. Skip folder layout and dependency lists.

Where it lives:

таблицю можна гортати вбік →
Level File For whom
user ~/.claude/CLAUDE.md You, in all projects
project ./CLAUDE.md The whole team, in git
directory a nested CLAUDE.md One folder; loads when Claude works there

The levels are added together; one does not replace another. On a conflict the more specific one wins: you say 2 spaces, the project says 4, it is 4.

@docs/style.md pulls in another file. It keeps things tidy but does not shrink the context: imported files load at launch.

Step 2. Rules

Files in .claude/rules/, one per topic.

  • With paths: (glob patterns) a rule loads only when Claude works on matching files.
  • Without paths: it always applies, like .claude/CLAUDE.md.

A pattern across the whole repo (every *.test.js) is a rule with paths:. Rules for one folder go into a CLAUDE.md in that folder.

Step 3. Hooks: where you need a guarantee

A hook is a script Claude Code runs on an event. Two matter for the exam:

таблицю можна гортати вбік →
Event When What it can do
PreToolUse Before a tool Allow it, modify the input or block it
PostToolUse After a tool Cannot undo it. Shapes the result for Claude, logs

PreToolUse is like HandlerInterceptor.preHandle: it can stop the call from going further. Canonical example: block any refund over $500 and route it to a human (lecture 9).

Step 4. Skills and commands

A skill is a folder with SKILL.md: instructions for a specific task.

  • The description is always in context; the rest loads only when invoked. So a long procedure is better moved out of CLAUDE.md into a skill.
  • disable-model-invocation: true: only you can run it (for deploys or commits).
  • context: fork: the skill runs in a separate context.
  • allowed-tools pre-approves the listed tools but does not block the others.
  • Slash commands (.claude/commands/*.md, $ARGUMENTS) are now merged into skills. On a name clash the skill wins.

Step 5. Subagents

A subagent is a helper with its own context window.

The main benefit: context isolation. It runs a bulky search in its own window and returns only a summary.

It does not see the main agent's conversation, so write everything it needs into its prompt (lecture 9). Its tools can be limited with the tools field. Built-in subagents: Explore (fast read-only search), Plan, general-purpose.

Step 6. Plan mode

A mode where Claude only reads and writes a plan, while Write and Edit are blocked until you approve. It is a block, not a request.

Turn it on with Shift+Tab twice, /plan or --permission-mode plan. Use it for large and risky changes (lecture 11).

Glossary

Term What it is
CLAUDE.md the instruction file read at session start
Rules separate rule files that can apply only to certain paths
Hook a script on an event that guarantees an action
Skill an instruction package loaded when needed
Subagent a separate agent with an isolated context
Plan mode a mode where Claude plans but cannot change files

What to remember for the exam

  1. CLAUDE.md advises, a hook guarantees.
  2. CLAUDE.md levels combine; the more specific wins.
  3. A pattern across the repo: a rule with paths:. One folder: a CLAUDE.md in it.
  4. PreToolUse can block, PostToolUse no longer can.
  5. allowed-tools pre-approves but does not restrict.
  6. A subagent gives context isolation.
  7. Plan mode blocks Write and Edit until approval.

Check yourself

  1. How do you guarantee that Claude will not change .env?
  2. You say 2 spaces, the project says 4. Which applies?
  3. Where do rules for every *.test.js in the repo go?
  4. What happens to other tools if a skill has allowed-tools: Read?
  5. What is the main benefit of a subagent?
Answers
  1. A PreToolUse hook that blocks changes to .env.
  2. 4: the more specific level wins.
  3. In a .claude/rules/ file with paths: ["**/*.test.js"].
  4. Nothing: they stay available as usual.
  5. Context isolation.
