Lecture 2: how an agent works with tools

Simplified version. The full lecture exists in Ukrainian only. The exam-course view of the loop is in lecture 9.

The main idea

The model runs nothing. It returns a request, and your code runs it.

Normally a client calls your controller. Here it is the other way round: the model is the client that sends you a request "call this method", and your code runs it and returns the result. The model itself cannot reach your database or API.

Why it is designed this way

The model only says "I need a tool". Your code runs it and returns the result, so you need the loop and stop_reason to know when to continue.

Step 1. What a tool is

A tool is your function, described for the model: a name, what it does and what parameters it takes.

Example: get_weather, "returns the current weather", parameter city.

The model does not see your code, only this description. So the better it is described, the more accurately the model calls it. It is like an OpenAPI contract: the client knows only the contract.

Step 2. One round of the conversation

The user asks: "What's the weather in Kyiv?"

Who What happens
You Send the question and the tool descriptions
The model Answers with a tool_use block: "call get_weather, city Kyiv"
Your code Actually calls the weather service: +15, cloudy
You Send a tool_result block with that result
The model Tells the user: "It's +15 and cloudy in Kyiv"

The model said what it wanted but did not run it. You did.

tool_use has an id, and in tool_result you give the same tool_use_id, so the model knows which request this answers.

Step 3. How to know what to do next: stop_reason

Every model reply has a stop_reason field, like a result status.

таблицю можна гортати вбік →
Value What it means What you do
tool_use The model asks for a call Run the tool, send the result
end_turn The model is done Show the answer, exit
max_tokens The answer was cut by the limit Raise the limit
refusal The model refused Look at stop_details

The loop in Java:

Response response = client.send(messages);
while ("tool_use".equals(response.stopReason())) {
    List<ToolResult> results = executeAll(response.toolUses());
    messages.add(response.asAssistantMessage());
    messages.add(userMessageOf(results));
    response = client.send(messages);
}
show(response);

Read it as: while the model asks for a call, run it and ask again.

Step 4. Three rules people get wrong

Rule 1. Several tools at once. The model can return three tool_use blocks in one reply. You run them all and return all results in one message. If you send them separately, the model "unlearns" asking for several at once.

Rule 2. The tool failed. Do not stay silent and do not crash. Return a tool_result with is_error: true and a clear text, for example: "Service unavailable, retry in 60 seconds". Then the model can try something else.

Rule 3. A round limit. The documentation does not limit the number of rounds. If the model keeps asking for tools, your while spins forever. Set your own limit, for example 10. It is the same as maxAttempts in a retry.

Step 5. Who runs the tool

таблицю можна гортати вбік →
Kind Who runs it Examples
Your own You get_weather, a query to your database
Ready-made from Anthropic You bash, text_editor, memory
Server tools Anthropic web_search, web_fetch, code_execution

For server tools you only switch the tool on, and the result arrives inside the finished reply.

Step 6. Two rare things

  • pause_turn. Server tools have their own inner loop limited to 10 rounds. When it hits the limit you get pause_turn: "not finished yet". Just send the conversation again.
  • disable_parallel_tool_use. Turns off parallel calls. The parameter lives inside tool_choice, not on its own.

Glossary

Term What it is
Agent loop request, model reply, tool call, request again
stop_reason why the model stopped: tool_use, end_turn, max_tokens and so on
tool_use / tool_result the block where the model asks for a tool, and the block with the result
Parallel calls several tool_use blocks in one reply; the results go back together
pause_turn a server tool paused the turn; continue it
Client / server tool run by your code, or run by Anthropic

What to remember for the exam

  1. The model asks, your code runs.
  2. The loop continues while stop_reason is tool_use.
  3. All results of one turn go in one message.
  4. A tool error: is_error: true and a clear text.
  5. You set the round limit yourself.
  6. pause_turn means "send it again".

Check yourself

  1. Who actually runs get_weather?
  2. What do you do when stop_reason is end_turn?
  3. The model asked for three tools. How many result messages?
  4. A tool failed. What do you return to the model?
  5. Why have your own round limit?
Answers
  1. Your code. The model only asks.
  2. Show the answer and leave the loop.
  3. One, with three results.
  4. A tool_result with is_error: true and a clear text.
  5. The documentation gives no limit, and the model can keep asking for tools.
