Лекція 5: Claude Code

Спрощена версія. Повна: ../5-claude-code-memory-hooks-skills-permissions-subagents.md. Деталі, яких тут нема (усі події hooks, всі ключі налаштувань), дивіться там.

Головна ідея

Одні речі лише радять моделі, інші примусово забороняють. Іспит постійно питає саме про цю різницю.

Лише радить Примусово діє
CLAUDE.md, rules, skills, auto memory Правила дозволів (deny), hooks з exit 2, managed settings, sandbox

Для Spring-розробника: CLAUDE.md це як README чи Javadoc (читають, але ніхто не змушений), а deny і hooks як Spring Security чи фільтр (порушити не можна).

Тому на питання «як гарантувати X» відповідь ніколи не «напишіть у CLAUDE.md».

Крок 1. CLAUDE.md

Це файл інструкцій, який Claude читає на початку кожної сесії. Це контекст, а не примусове правило.

Правила для доброго файла:

  • до 200 рядків;
  • конкретні інструкції («Use 2-space indentation», а не «форматуй гарно»);
  • лише факти, потрібні в кожній сесії. Покрокові процедури краще в skill, а частину коду в rule з paths.

Де лежить: ~/.claude/CLAUDE.md (для вас), ./CLAUDE.md (для проєкту), ./CLAUDE.local.md (особисте, у .gitignore).

Усі знайдені файли додаються разом, а не перекривають один одного. Файли в підкаталогах вантажаться, коли Claude торкається файлів там.

Крок 2. AGENTS.md

Загальний формат інструкцій для різних агентів. Правило читання:

У репозиторії Claude читає
лише AGENTS.md AGENTS.md
AGENTS.md і CLAUDE.md лише CLAUDE.md
CLAUDE.md, що імпортує @AGENTS.md обидва

Тому в ai-ops CLAUDE.md просто містить @AGENTS.md.

Крок 3. Rules і auto memory

  • Rules (.claude/rules/): окремі файли по темах. З paths вантажаться лише коли Claude працює з файлами за цим патерном.
  • Auto memory: нотатки, які Claude пише сам. Індекс MEMORY.md вантажиться на старті (перші 200 рядків чи 25 КБ), а файли тем лише на вимогу. Пам'ять локальна для машини.

Крок 4. Дозволи

Три типи правил: deny, ask, allow. Перевірка йде саме в цьому порядку, перший збіг вирішує.

Звідси головне: allow не може зробити виняток із deny. Якщо в deny Bash(aws *), то Bash(aws s3 ls) у allow не допоможе.

Правила виконує сам Claude Code, а не модель. Промпт чи CLAUDE.md їх не змінюють.

Режими

Режим Що робить
default Питає при першому використанні інструмента
acceptEdits Сам приймає редагування файлів
plan Лише читає й планує, без змін
auto Окрема модель-класифікатор перевіряє дії
dontAsk Відмовляє у всьому, що питало б (для CI)
bypassPermissions Без запитів, лише для ізольованих середовищ

У bypassPermissions правила deny діють, а allow ні.

Правила Bash

  • Зірочку ставте після підкоманди: Bash(git log *) дозволяє лише git log, а Bash(git *) усі git-команди.
  • Складена команда (a && b) іде без запиту, лише якщо кожна частина дозволена.
  • Правило Bash не є межею безпеки. Bash(curl *) не зупинить sh -c 'curl ...' чи /usr/bin/curl. Для цього потрібна пісочниця чи hook.

Правила для файлів

  • Read(./.env) у deny блокує читання, а також Edit і Write на цьому шляху.
  • Правила Grep(...), Glob(...) і Write(...) зі шляхом не діють: пишіть Read(...) чи Edit(...).
  • Файл .claudeignore не діє: переносьте в Read deny.

Крок 5. Hooks

Hook це скрипт (чи запит), який Claude Code запускає на певну подію. Найважливіше:

Подія Коли Що можна
PreToolUse Перед інструментом Заблокувати
PostToolUse Після інструмента Нічого скасувати (вже виконано)
UserPromptSubmit Перед обробкою промпта Заблокувати чи додати контекст
Stop Коли Claude закінчив відповідати Не дати зупинитись
SessionStart На початку сесії (з compact після ущільнення) Додати контекст

Для Spring-розробника PreToolUse схожий на HandlerInterceptor.preHandle: може не пропустити виклик далі.

Коди виходу

Код Що відбувається
0 Успіх
2 Блокує дію (stderr іде моделі як причина)
інший, зокрема 1 Не блокує, дія триває

2 блокує, 1 ні.

Що ще знати

  • Рішення можна повернути JSON-ом у hookSpecificOutput (permissionDecision: allow, deny, ask, defer). Поле на верхньому рівні мовчки ігнорується.
  • deny у hook діє навіть у bypassPermissions.
  • Кілька hooks на одну подію виконуються паралельно, найсуворіше рішення виграє (deny > defer > ask > allow).
  • Stop hook спрацьовує після кожної відповіді. Після 8 блокувань поспіль Claude Code перекриває його. Скрипт має перевіряти поле stop_hook_active.
  • Якщо hook впав чи вийшов таймаут, дія триває (щоб блокувати, потрібен onFailure: "block").
  • JSON у hook не діє, якщо перед ним щось друкує профіль оболонки (вивід має починатись із {).

Крок 6. Skills

Skill це папка з SKILL.md: інструкції для певної задачі.

  • Опис завжди в контексті, повне тіло лише коли skill викликано.
  • Дуже довгу процедуру винесіть із CLAUDE.md у skill: вона не коштує контексту, доки не потрібна.
  • disable-model-invocation: true: skill можете запустити лише ви (для деплою).
  • context: fork: skill виконується в окремому субагенті.

Крок 7. Субагенти

Субагент це помічник з окремим вікном контексту.

Головна користь: ізоляція контексту. Він виконує громіздкий пошук у своєму вікні й повертає лише підсумок.

Можна обмежити його інструменти (tools) і дозволи. Вбудовані: Explore (швидкий пошук лише для читання), Plan, general-purpose.

Ліміти за замовчуванням: до 3 рівнів вкладення, до 20 одночасно.

Крок 8. Налаштування

Пріоритет від найвищого: managed, командний рядок, local, shared project, user. Списки (наприклад, allow) зливаються, а не перекриваються. Це схоже на порядок джерел властивостей у Spring.

Managed settings це налаштування організації, які користувач не може обійти.

Крок 9. Sandbox (коротко)

Це межа рівня операційної системи навколо shell-команд (Bash, PowerShell, Monitor). Вимкнений за замовчуванням. Файлові інструменти, MCP і hooks поза ним.

Деталі в лекції 8.

Що запам'ятати на іспит

  1. CLAUDE.md радить. Deny, hooks і managed settings примушують.
  2. Порядок правил: deny, ask, allow. Allow не вирізає виняток із deny.
  3. Exit 2 блокує, exit 1 ні.
  4. deny у hook і в правилах діє навіть у bypassPermissions.
  5. Правило Bash не межа безпеки.
  6. MEMORY.md на старті: 200 рядків чи 25 КБ.
  7. AGENTS.md читається, лише коли нема CLAUDE.md (чи через імпорт).
  8. Субагент дає ізоляцію контексту.
  9. Stop hook: 8 продовжень поспіль, перевіряйте stop_hook_active.

Перевірте себе

  1. Як гарантувати, що Claude не змінить .env?
  2. Що робить hook із кодом виходу 1?
  3. Що виграє: deny Bash(aws *) чи allow Bash(aws s3 ls)?
  4. Скільки MEMORY.md вантажиться на старті?
  5. Яка основна користь субагента?
  6. Що з skill завжди в контексті?
