Лекція 11: налаштування Claude Code і робочі процеси (домен 3)

За курсом до іспиту, домен 3: Claude Code Configuration & Workflows. Картки груп «Claude Code: пам'ять і налаштування» та «Claude Code: команди й CI», тест «Домен 3». Деталі про дозволи й hooks у лекції 5.

Головна ідея

Пояснюєте проєкт один раз, а не щосесії. Постійні правила йдуть у CLAUDE.md і .claude/rules, повторювані дії в команди й навички, ризикова робота в plan mode, автоматична в CI.

Крок 1. Ієрархія CLAUDE.md

CLAUDE.md це записка, яку Claude читає на початку кожної сесії: команди збірки, домовленості, підводні камені.

таблицю можна гортати вбік →
Рівень Де лежить Для чого
user ~/.claude/CLAUDE.md Ваші вподобання в усіх проєктах
project ./CLAUDE.md Правила команди, у git
directory вкладений CLAUDE.md Правила однієї папки

Над усім стоїть політика організації (managed).

  • Рівні складаються в один контекст, а не замінюють один одного.
  • При конфлікті перемагає конкретніший. У вас 2 пробіли, у проєкті 4: діє 4.
  • Вкладений frontend/CLAUDE.md вантажиться, лише коли Claude працює з файлами цієї папки. Це рятує великі монорепозиторії.
  • @docs/style.md імпортує інший файл. Імпорт тримає порядок, але контекст не зменшує: імпортоване вантажиться на старті.
  • /memory відкриває файли пам'яті для редагування.

Що писати: те, чого Claude не вгадає (пастки, відхилення від звичного, причину правила). Що не писати: структуру папок, список залежностей. Тримайте файл до приблизно 200 рядків: роздутий CLAUDE.md виконується гірше.

Крок 2. Правила для частини коду: .claude/rules

  • Кожен .md у .claude/rules/ вантажиться як пам'ять проєкту, з тим самим пріоритетом, що .claude/CLAUDE.md.
  • З frontmatter paths: (список glob-шаблонів) правило вантажиться лише для відповідних файлів. Наприклад paths: ["src/api/**"].
  • Без paths: правило діє завжди.
Потрібно Що обрати
Шаблон через увесь репозиторій (кожен *.test.js) Rule з paths:
Усе в одній папці CLAUDE.md у цій папці

Правила за шляхами додаються останніми, тож при конфлікті вони перемагають: від широкого до конкретного.

Крок 3. Команди й навички

Slash-команда це Markdown-файл:

  • .claude/commands/ для всієї команди (у git) або ~/.claude/commands/ лише для вас;
  • ім'я файла стає командою, тіло стає промптом;
  • $ARGUMENTS підставляє ваш ввід: fix-issue.md запускають як /fix-issue 123.

Frontmatter команди: description (видно в /help, Claude може запропонувати команду), argument-hint, allowed-tools, model.

Навичка це розширена команда: .claude/skills/<name>/SKILL.md теж дає /name, але має папку для додаткових файлів і Claude може викликати її сам. Команди тепер злиті з навичками. Однакові імена: перемагає навичка.

Три поля, які любить іспит:

Поле Що робить
context: fork Запускає навичку в ізольованому контексті
allowed-tools Дозволяє перелічені інструменти без запиту. Інші не блокує
disable-model-invocation: true Викликати можете лише ви: для /commit, /deploy

CLAUDE.md чи команда? Постійні домовленості в CLAUDE.md (діють завжди). Повторювані дії як команда чи навичка (на вимогу).

Крок 4. Plan mode

Plan mode це режим лише для читання: Claude досліджує й пише план, а Write і Edit заблоковано на рівні інструментів, доки ви не схвалите план. Це не прохання, а блокування.

Як увімкнути: Shift+Tab двічі, /plan або --permission-mode plan (працює і з -p).

Плануйте Не треба
Кілька файлів, рефакторинг, міграції Правка в одному файлі
Автентифікація, платежі, продакшн Дрібні швидкі зміни
Незнайомий код, розмита задача

Цикл: дослідити, спланувати, схвалити (або спершу виправити план), виконати, перевірити тестами.

Explore subagent це розвідник лише з Read, Grep і Glob. Він читає в окремому контексті й повертає тільки висновки, тож важке читання не засмічує вашу сесію.

Крок 5. Ітерації

  • Перший результат це чернетка.
  • Покажіть приклад входу й виходу: це прибирає здогадки краще за довгий опис.
  • Interview pattern: попросіть Claude спершу розпитати вас (фреймворк, помилки, крайні випадки). Розмите прохання стає специфікацією.
  • Тест спершу: напишіть тест, який має пройти, і нехай Claude ітерує до зеленого.
  • Незалежні виправлення робіть разом, залежні по черзі.

Крок 6. Claude Code в CI/CD

  • claude -p "промпт" це headless-режим: виконує, друкує результат, виходить з кодом статусу.
  • --output-format json дає результат і метадані (cost, session_id), їх читають через jq. Формати: text, json, stream-json.
  • --json-schema гарантує форму результату в structured_output: беріть його, коли наступний крок вирішує щось за результатом.
  • Обмеження, бо ніхто не дивиться: --max-turns, --allowedTools, --max-budget-usd. Перевіряйте зміст результату, а не лише код виходу.
  • CLAUDE.md вантажиться і в CI: ваші правила стають контекстом рецензента.
  • Рев'ю робить окремий екземпляр: він не бачив міркувань автора й не виправдовує своїх рішень.

Що запам'ятати на іспит

  • CLAUDE.md: user, project, directory складаються, конкретніший перемагає.
  • Шаблон через репозиторій: rule з paths:. Одна папка: CLAUDE.md у ній.
  • allowed-tools дозволяє, але не обмежує.
  • disable-model-invocation: true для команд з побічними діями.
  • Plan mode блокує Write і Edit до схвалення.
  • CI: -p, --output-format json, --json-schema, ліміти ходів і бюджету.

  4. Як гарантувати форму результату claude -p?
