Lecture 7: compaction, thinking and memory

Simplified version. The full lecture exists in Ukrainian only.

The main idea

A long conversation does not fit in the window, so the old part is replaced by a short summary. The model's thinking has strict rules about how it is sent back. And memory keeps what must survive the summary.

Why it is designed this way

A long conversation does not fit in the context, so the old part is squeezed into a summary (compaction), and what matters is kept in external memory.

Part 1. Compaction

The server writes the summary of the old part itself; you write no summarizing code.

There are two modes:

The documentation recommends on-demand mode where it is available. Both are in beta.

On-demand mode

  1. Send the conversation with "compaction": {"type": "summarize"}.
  2. The reply: one compaction block and stop_reason: "compaction". There is no model answer.
  3. Put this block first in messages and remove the summarized messages.
  4. Send the block exactly as received, with its signature. Exactly one block per request.

Two mistakes that produce no error message:

  • the summarized messages stayed after the block: the API sends them to the model again;
  • the block was not added to the next request: the model does not see the summary.

If the summarized messages stayed before the block, you get 400.

More rules:

  • compaction and context_management cannot be in the same request;
  • your own summary prompt: instructions up to 16,384 characters; it fully replaces the default one. Say what to keep and tell it not to call tools;
  • if no summary was produced, the reply is still 200 with empty content, so check stop_reason;
  • images, documents, uploads and fetched URLs in the summarized part disappear.

Threshold mode

  • Default threshold 150,000 input tokens, minimum 50,000.
  • The block arrives at the start of the reply; append the full response.content together with it.
  • If the request has tools, the model sometimes calls a tool instead of summarizing, and the block has content: null. Then forbid tool calls in instructions.
  • You can stop after the summary (pause_after_compaction) to keep the last messages.

Cost

Summarizing costs money too. Sum usage.iterations, not the top-level input_tokens and output_tokens (they do not include compaction).

Part 2. Thinking

New models have adaptive thinking: the model decides whether and how much to think. A thinking block comes before the text and has a signature: an encrypted copy of the full thinking.

How to show thinking: display

Value What you get
summarized A short summary of the thinking is visible
omitted The block arrives empty, the signature stays (the default on Claude 5 models and newer)
updates (beta) Short progress updates between calls

omitted gives lower latency to the first text token, at the same cost. You pay for the full generated thinking, not the visible summary.

What you cannot do

  • thinking: enabled with budget_tokens on new models (Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable, Mythos, Opus 5, Sonnet 5, Opus 4.8 and 4.7) returns 400.
  • You cannot switch thinking mode in the middle of a turn with tool calls: the API silently turns thinking off for that request. Switch between turns.
  • From API version 2026-10-21 any value of temperature, top_p, top_k returns 400 on every model.

How to send blocks back

  • Within a turn with tools, thinking blocks must be sent back unchanged.
  • A modified block returns 400.
  • There is also redacted_thinking: encrypted blocks with no text; they are also sent back unchanged. A typical bug: a block.type == "thinking" filter silently drops them and breaks the protocol.

Part 3. The memory tool

A tool Claude uses to save and read files between conversations.

It is a client tool: Claude only asks for an operation, and your application performs it on storage you control.

  • Files live in the /memories directory (your code maps it onto real storage).
  • Commands: view, create, str_replace, insert, delete, rename.
  • The root /memories cannot be deleted or renamed.

Security is on you. A path like /memories/../../secrets.env escapes the directory (path traversal). Check every path: it starts with /memories, canonicalise it, reject ../ and %2e%2e%2f.

Memory is combined with compaction: the summary keeps the general picture, and memory keeps everything that must survive the summary.

A multi-session pattern: the first session creates a progress log and a checklist, each next session starts by reading them and updates the log at the end. Mark a feature done only after an end-to-end check.

Glossary

Term What it is
Compaction block a block with a summary that replaces the old part of the conversation
Thinking the model's reasoning before the answer
Adaptive thinking the model chooses how deeply to think
Memory tool a tool that keeps notes in files between conversations
Client tool run by your code; security is on you
Compaction instructions a hint about what exactly to keep in the summary

What to remember for the exam

  1. Two compaction modes: on demand (block first, you remove the summarized part) and by threshold (150,000, minimum 50,000).
  2. The cost is the sum of usage.iterations.
  3. No summary still means 200 with empty content: check stop_reason.
  4. display: omitted saves latency, not money.
  5. enabled with budget_tokens on new models returns 400.
  6. Thinking is not switched in the middle of a turn with tools.
  7. temperature in API version 2026-10-21 returns 400 on all models.
  8. redacted_thinking is also sent back unchanged.
  9. The memory tool is a client tool: you protect against path traversal.

Check yourself

  1. Where does the compaction block go in on-demand mode?
  2. How do you calculate the cost with compaction?
  3. What happens if the summarized messages stayed after the block?
  4. What does display: omitted save?
  5. What happens if you switch thinking in the middle of a turn with tools?
  6. Who performs memory tool operations?
  7. What is the most important check in its handler?
Answers
  1. First in messages; remove the summarized messages.
  2. The sum of the usage.iterations entries.
  3. No error; the API sends them to the model again.
  4. Latency to the first token. The cost is the same.
  5. The API silently turns thinking off for that request.
  6. Your application.
  7. That the path stays inside /memories (canonicalisation, rejecting ../).
