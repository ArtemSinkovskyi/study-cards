Лекція 7: ущільнення розмови, роздуми й пам'ять

Спрощена версія. Повна: ../7-compaction-thinking-and-memory-tool.md. Повні таблиці моделей і коди помилок лишились лише там.

Головна ідея

Довга розмова не влазить у вікно, тому стару частину замінюють коротким підсумком. Роздуми моделі мають свої строгі правила повернення. А пам'ять зберігає те, що має пережити підсумок.

Навіщо це так задумано

Довга розмова не вміщується в контекст, тому стару частину стискають у підсумок (compaction), а важливе зберігають у зовнішній пам'яті.

Частина 1. Ущільнення (compaction)

Сервер сам пише підсумок старої частини розмови, і ви не пишете жодного коду підсумовування.

Є два режими:

Хто вирішує, коли Ви API, коли вхід сягає порогу

Beta-заголовок compact-2026-09-04 compact-2026-01-12

Документація радить режим за запитом, де він доступний. Обидва в beta.

Режим за запитом

  1. Надсилаєте розмову з "compaction": {"type": "summarize"}.
  2. Відповідь: один блок compaction і stop_reason: "compaction". Відповіді моделі нема.
  3. Ставите цей блок першим у messages і прибираєте підсумовані повідомлення.
  4. Блок шлете точно як отримали, з підписом. Рівно один блок на запит.

Дві помилки, які не дають жодного повідомлення:

  • підсумовані повідомлення лишились після блока: API знову відправить їх моделі;
  • блок не додали в наступний запит: модель не бачить підсумку.

Якщо підсумовані повідомлення лишились перед блоком, буде 400.

Ще правила:

  • compaction і context_management не можна в одному запиті;
  • свій промпт підсумку: instructions до 16 384 символів, він повністю замінює стандартний. Скажіть, що зберегти, і не викликати інструментів;
  • якщо підсумку не вийшло, відповідь усе одно 200 із порожнім вмістом, тож перевіряйте stop_reason;
  • зображення, документи, завантаження й отримані URL у підсумованому зникають.

Режим за порогом

  • Поріг за замовчуванням 150 000 вхідних токенів, мінімум 50 000.
  • Блок приходить на початку відповіді; додавайте повний response.content разом із ним.
  • Якщо в запиті є tools, модель інколи викликає інструмент замість підсумку, і блок має content: null. Тоді в instructions забороніть виклики інструментів.
  • Можна зупинитись після підсумку (pause_after_compaction), щоб зберегти останні повідомлення.

Вартість

Підсумовування теж коштує. Рахуйте суму usage.iterations, а не верхні input_tokens і output_tokens (вони не включають ущільнення).

Частина 2. Роздуми (thinking)

Нові моделі мають adaptive thinking: модель сама вирішує, думати й скільки. Блок thinking іде перед текстом і має signature: зашифровану копію повних роздумів.

Як показувати роздуми: display

Значення Що дає
summarized Видно короткий підсумок роздумів
omitted Блок приходить порожнім, підпис лишається
updates (beta) Короткі оновлення прогресу між викликами

omitted дає менше затримки до першого токена тексту, а вартість та сама. Платите за повні згенеровані роздуми, а не за видимий підсумок.

Що не можна

  • thinking: enabled з budget_tokens на нових моделях (Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable, Mythos, Opus 5, Sonnet 5, Opus 4.8 і 4.7) дає 400.
  • Перемикати режим thinking посеред ходу з викликами інструментів не можна: API мовчки вимкне роздуми для того запиту. Перемикайте між ходами.
  • З версії API 2026-10-21 будь-яке значення temperature, top_p, top_k дає 400 на кожній моделі.

Як повертати блоки

  • У межах ходу з інструментами блоки thinking обов'язково повертають без змін.
  • Змінений блок дає 400.
  • Є також redacted_thinking: зашифровані блоки без тексту, їх теж повертають без змін. Типова помилка: фільтр block.type == "thinking" мовчки губить їх і ламає протокол.

Частина 3. Memory tool

Це інструмент, яким Claude зберігає й читає файли між розмовами.

Він клієнтський: Claude лише просить операцію, а виконує ваш застосунок над сховищем, яке ви контролюєте.

  • Файли лежать у каталозі /memories (ваш код відображає його на реальне сховище).
  • Команди: view, create, str_replace, insert, delete, rename.
  • Кореневий /memories не можна видалити чи перейменувати.

Безпека лежить на вас. Шлях типу /memories/../../secrets.env виходить за каталог (path traversal). Перевіряйте кожен шлях: починається з /memories, канонізуйте, відхиляйте ../ і %2e%2e%2f.

Пам'ять поєднують із ущільненням: підсумок зберігає загальне, а пам'ять усе, що має пережити підсумок.

Багатосесійний шаблон: перша сесія створює журнал прогресу й чекліст, кожна наступна починає з їх читання, наприкінці оновлює журнал. Функцію позначайте завершеною лише після наскрізної перевірки.

Що запам'ятати на іспит

  1. Два режими ущільнення: за запитом (блок першим, ви прибираєте підсумовані) і за порогом (150 000, мінімум 50 000).
  2. Вартість це сума usage.iterations.
  3. Без підсумку приходить 200 із порожнім вмістом: перевіряйте stop_reason.
  4. display: omitted економить затримку, не гроші.
  5. enabled з budget_tokens на нових моделях дає 400.
  6. Thinking не перемикають посеред ходу з інструментами.
  7. temperature у версії API 2026-10-21 дає 400 на всіх моделях.
  8. redacted_thinking теж повертають без змін.
  9. Memory tool клієнтський: path traversal захищаєте ви.

Перевірте себе

  1. Де має стояти блок compaction у режимі за запитом?
  2. Як порахувати вартість із ущільненням?
  3. Що станеться, якщо підсумовані повідомлення лишились після блока?
  4. Що економить display: omitted?
  5. Що буде, якщо перемкнути thinking посеред ходу з інструментами?
  6. Хто виконує операції memory tool?
  7. Яка найважливіша перевірка в його обробнику?
Відповіді
  1. Першим у messages, підсумовані повідомлення прибрати.
  2. Сума записів usage.iterations.
  3. Помилки не буде, API знову надішле їх моделі.
  4. Затримку до першого токена. Вартість та сама.
  5. API мовчки вимкне роздуми для того запиту.
  6. Ваш застосунок.
  7. Що шлях лишається в /memories (канонізація, відмова ../).
