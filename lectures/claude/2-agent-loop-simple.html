Лекція 2: як агент працює з інструментами

Спрощена версія. Повна: ../2-agentic-loop-and-tool-use.md. Погляд курсу на цикл агента в лекції 9.

Що з цього питають на іспиті

Коли цикл продовжується, а коли зупиняється. Як повертати результати кількох інструментів. Що робити, коли інструмент упав.

Головна ідея

Модель нічого не виконує. Вона просить, а виконує твій код.

Зазвичай клієнт кличе твій контролер. Тут навпаки: модель це клієнт, який надсилає тобі запит «виклич такий метод». Твій код його виконує й повертає результат. Сама модель до твоєї бази чи API не дотягнеться.

Крок 1. Що таке інструмент

Інструмент це твоя функція, описана для моделі: назва, що вона робить і які параметри приймає.

Приклад: get_weather, «повертає поточну погоду», параметр city.

Модель бачить лише опис, а не код. Що точніший опис, то точніше вона викликає інструмент. Це як OpenAPI-контракт: клієнт знає тільки його.

Крок 2. Одне коло розмови

Користувач питає: «Яка погода в Києві?»

Хто Що відбувається
Ти Надсилаєш питання й описи інструментів
Модель Відповідає блоком tool_use: «виклич get_weather, місто Київ»
Твій код Справді звертається до погодного сервісу: +15, хмарно
Ти Надсилаєш блок tool_result із цим результатом
Модель Пише користувачу: «У Києві +15, хмарно»

Модель сказала, чого хоче, але нічого не виконала. Виконав твій код.

У tool_use є id. У tool_result ти вказуєш той самий tool_use_id, щоб модель знала, на який запит це відповідь.

Крок 3. Як зрозуміти, що далі: stop_reason

Кожна відповідь моделі має поле stop_reason, щось на зразок статусу.

таблицю можна гортати вбік →
Значення Що означає Що робиш
tool_use Модель просить виклик Виконуєш інструмент, надсилаєш результат
end_turn Модель закінчила Показуєш відповідь і виходиш
max_tokens Відповідь обрізав ліміт Збільшуєш ліміт
refusal Модель відмовилась Дивишся stop_details

Цикл на Java:

Response response = client.send(messages);
while ("tool_use".equals(response.stopReason())) {
    List<ToolResult> results = executeAll(response.toolUses());
    messages.add(response.asAssistantMessage());
    messages.add(userMessageOf(results));
    response = client.send(messages);
}
show(response);

Читається просто: поки модель просить виклик, виконуємо й питаємо знову.

Крок 4. Три правила, на яких помиляються

Кілька інструментів за раз. Модель може повернути три tool_use в одній відповіді. Виконуєш усі й повертаєш усі результати одним повідомленням. Якщо слати окремо, модель відвикає просити кілька викликів одночасно.

Інструмент упав. Не мовчи й не падай. Поверни tool_result з is_error: true і зрозумілим текстом, наприклад «Сервіс недоступний, повтори за 60 секунд». Тоді модель спробує інакше.

Ліміт кіл. Документація кількість кіл не обмежує. Якщо модель без кінця просить інструменти, твій while крутитиметься вічно. Постав свій ліміт, наприклад 10, як maxAttempts у retry.

Крок 5. Хто виконує інструмент

таблицю можна гортати вбік →
Вид Хто виконує Приклади
Твої власні Ти get_weather, запит у твою базу
Готові від Anthropic Ти bash, text_editor, memory
Серверні Anthropic web_search, web_fetch, code_execution

Серверний інструмент ти лише вмикаєш, а результат приходить уже в готовій відповіді.

Крок 6. Дві рідкісні речі

  • pause_turn. Серверні інструменти мають власний цикл до 10 кіл. Коли він вичерпується, приходить pause_turn: «ще не закінчено». Просто надішли розмову знову.
  • disable_parallel_tool_use. Вимикає паралельні виклики. Параметр лежить усередині tool_choice, а не окремо.

Словник

Термін Що це
Agent loop цикл: запит, відповідь моделі, виклик інструмента, знову запит
stop_reason чому модель зупинилась: tool_use, end_turn, max_tokens тощо
tool_use / tool_result блок, де модель просить інструмент, і блок із результатом
Паралельні виклики кілька tool_use в одній відповіді, результати йдуть назад разом
pause_turn серверний інструмент зробив паузу, треба продовжити

Що запам'ятати на іспит

  1. Модель просить, твій код виконує.
  2. Цикл триває, поки stop_reason дорівнює tool_use.
  3. Усі результати одного ходу йдуть одним повідомленням.
  4. Помилка інструмента: is_error: true і зрозумілий текст.
  5. Ліміт кіл ставиш сам.
  6. pause_turn означає «надішли ще раз».

Перевір себе

  1. Хто насправді виконує get_weather?
  2. Що робити, коли stop_reason дорівнює end_turn?
  3. Модель попросила три інструменти. Скільки повідомлень із результатами?
  4. Інструмент упав. Що повертаєш моделі?
  5. Навіщо власний ліміт кіл?
Відповіді
  1. Твій код. Модель лише просить.
  2. Показати відповідь і вийти з циклу.
  3. Одне, з трьома результатами.
  4. tool_result з is_error: true і зрозумілим текстом.
  5. Бо документація ліміту не дає, а модель може просити інструменти без кінця.
