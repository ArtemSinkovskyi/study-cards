Лекція 29: Athena, OpenSearch, MSK, SES і ще кілька сервісів

Середній рівень: усі правила з повної лекції, але простими словами. Повна: ../29-other-aws-services.md. Це теорія, в AWS ми цього не виконували. Сертифікати, Macie і AppConfig тут коротко: докладніше в лекціях про KMS і CI/CD. Не звірене позначено (не звірено).

Головна ідея

Кожен із цих сервісів вирішує одну вузьку задачу: Athena це SQL по файлах у S3, OpenSearch це пошук за будь-яким полем, MSK це Kafka, SES це пошта. На іспиті питають, який із них обрати.

Навіщо це так задумано

AWS не змушує тягти все в одну базу. Для файлів є Athena, для пошуку OpenSearch, для потоків Kinesis або Kafka. Кожен інструмент швидкий у своєму і слабкий у чужому.

Крок 1. Athena

Athena це безсерверний SQL по файлах у S3. Нічого не завантажуєте в базу: пишете SQL, Athena читає файли напряму.

  • Формати: CSV, JSON, ORC, Avro, Parquet.
  • Типові задачі: звіти й аналітика, аналіз логів VPC Flow Logs, ELB Logs, CloudTrail.
  • Підказка: «аналізувати дані в S3 безсерверним SQL» означає Athena.

Як зробити запити швидшими й дешевшими

Athena бере гроші за кількість просканованих даних. Тож треба сканувати менше:

  1. Колонкові формати (Parquet, ORC): читаються лише потрібні колонки.
  2. Стиснення (gzip, zstd, snappy, bzip2, lz4, zlib): менше байтів, платите за байти до розпакування.
  3. Partitioning: розкладіть дані по теках S3 за ознакою (наприклад, за датою), тоді запит із фільтром по даті читає лише потрібні теки.
  4. Великі файли (понад 128 МБ): менше накладних витрат. Багато малих файлів гальмує.

У нотатках було «zlip»: це описка, правильно zlib.

Federated Query

Запит SQL одразу до кількох різних джерел (CloudWatch Logs, DynamoDB, RDS та інші, навіть поза AWS). Для цього використовують connectors, що працюють на Lambda. Результат можна покласти назад у S3.

Крок 2. OpenSearch

OpenSearch це наступник Amazon Elasticsearch Service. Навіщо він, якщо є DynamoDB?

  • DynamoDB шукає лише за ключем або індексом.
  • OpenSearch шукає за будь-яким полем, навіть за частиною слова.

Ще:

  • два режими: керований кластер або serverless;
  • безпека: Cognito, IAM, KMS, TLS;
  • SQL нативно не основна мова, але SQL-підтримку можна ввімкнути (в нотатках «плагін») (уточнено за документацією).

Схема «DynamoDB плюс OpenSearch» (складена з двох фактів нотаток, не звірена):

  1. Застосунок пише в DynamoDB.
  2. DynamoDB Streams віддає зміну в Lambda.
  3. Lambda кладе документ в OpenSearch.
  4. Пошук іде в OpenSearch, а за знайденим ключем дані беруть з DynamoDB.

Фраза-підказка: «повнотекстовий пошук по даних DynamoDB» означає OpenSearch.

Крок 3. MSK

MSK це керований Apache Kafka, альтернатива Kinesis.

  • MSK створює й керує вузлами-брокерами Kafka та вузлами ZooKeeper. У новіших кластерах замість ZooKeeper може бути KRaft.
  • Кластер у вашій VPC, у кількох зонах доступності (у нотатках «до 3» (не звірено)).
  • Дані на EBS-томах (не звірено).
  • MSK Serverless: Kafka без керування потужністю, MSK сам виділяє ресурси.

Крок 4. SES

SES це сервіс листів: надсилає й отримує пошту безпечно й у великому масштабі.

  • панель репутації, показники доставки, зворотний зв'язок про спам;
  • повідомлення про bounce і скарги йдуть через SNS;
  • автентифікація листів: Easy DKIM;
  • вхідні листи можна класти в S3 і запускати Lambda.

Крок 5. Сертифікати, Macie, AppConfig: коротко

ACM підключається до Elastic Load Balancers, CloudFront і API Gateway. Private CA видає сертифікати X.509 для користувачів, комп'ютерів, API та IoT-пристроїв.

Macie

Знаходить чутливі дані (PII) в S3 за допомогою машинного навчання й шаблонів.

AppConfig

Змінює налаштування застосунку без нового деплою: feature flags, налаштування, allow/block-списки. Перед розгортанням перевіряє зміну двома способами:

  • JSON Schema: перевірка синтаксису;
  • Lambda: ваш код перевіряє зміст (семантику).

Що запам'ятати на іспит

  1. SQL по S3 без серверів: Athena. Дешевше з Parquet, стисненням, партиціями, великими файлами.
  2. Федеративний запит: connectors на Lambda, результат у S3.
  3. Пошук за будь-яким полем: OpenSearch.
  4. Kafka як сервіс: MSK; Serverless без керування потужністю.
  5. MSK: теми й розділи; Kinesis: шарди.
  6. ACM безкоштовний, Private CA для внутрішніх сертифікатів.
  7. PII в S3: Macie. Конфіг без деплою: AppConfig.
