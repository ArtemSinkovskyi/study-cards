Лекція 25: VPC, своя мережа в AWS

Середній рівень: усі правила з повної лекції, але простими словами. Повна: ../25-vpc-networking.md. Усе звірено з документацією AWS; що не підтверджено, позначено (не звірено). В AWS це не виконували.

Головна ідея

VPC це ваша власна ізольована мережа в AWS. Ви самі вирішуєте, що в ній видно ззовні, а що ні. На іспиті потрібно знати складові, різницю між security group і NACL та способи з'єднувати VPC із чимось іще.

Навіщо це так задумано

Без VPC усі ресурси були б у спільній мережі. VPC дає кімнату з дверима: хто заходить і виходить, вирішуєте ви. Підмережі дають кімнати всередині кімнати: публічну для сайту, приватну для бази.

Крок 1. Словник

Термін Суть
Subnet частина VPC, публічна чи приватна
Route table вказівник «куди йде трафік»
Internet Gateway двері в інтернет для публічних підмереж
NAT Gateway двері «лише назовні» для приватних підмереж
Security group фаєрвол на сервері
Network ACL фаєрвол на всю підмережу

Крок 2. Складові

Складова Що робить
Subnet ділить VPC на публічні й приватні зони
Route Table визначає, куди маршрутизується трафік
Internet Gateway доступ до інтернету для публічних підмереж
NAT Gateway вихід у інтернет для приватних підмереж
Security Group керує входом і виходом ресурсу
Network ACL правила на рівні підмережі

Шлях запиту ззовні: IGW, потім route table, потім NACL підмережі, потім SG сервера. Lambda потрапляє у VPC лише якщо ви це налаштували, а без NAT Gateway вона не має виходу в інтернет.

Крок 3. Security group чи NACL

таблицю можна гортати вбік →
Security group NACL
Де на сервері на підмережі
Правила лише дозволи дозволи й заборони
Пам'ять stateful: відповідь дозволена сама stateless: відповідь дозволяти окремо
Порядок усі правила разом за номером, до першого збігу

Правило: заблокувати конкретну IP-адресу можна лише в NACL. SG не має заборон. Стандартний NACL дозволяє все (з нотаток, не звірено окремо). Документація радить спершу SG, NACL як додатковий шар.

Крок 4. NAT Gateway

Приватний сервер хоче скачати оновлення з інтернету. Без NAT він не може. NAT Gateway:

  1. стоїть у публічній підмережі й має Elastic IP;
  2. приймає запит від приватного сервера й виходить у інтернет від свого імені;
  3. повертає відповідь, але нових вхідних з'єднань ззовні не пускає.

Крок 5. П'ять способів зв'язності

Спосіб Суть
VPC Peering дві VPC, можна в різних регіонах і акаунтах; приватні IP; не транзитний
Gateway endpoint приватний шлях до S3 і DynamoDB
Interface endpoint приватний шлях до інших сервісів (PrivateLink)
Site-to-Site VPN зашифрований тунель до вашого офісу через інтернет, два тунелі
Direct Connect виділений фізичний канал без інтернету

Peering: A з'єднано з B, B з'єднано з C, але A з C не з'єднано. Direct Connect надійний і швидкий, але потребує фізичного підключення.

Крок 6. Flow Logs

Це журнал, хто з ким спілкувався в мережі. Збирають на рівні VPC, підмережі чи окремого мережевого інтерфейсу. Допомагають знайти, чому не проходить зв'язок. Журнали можна надіслати в CloudWatch Logs, S3 або Amazon Data Firehose. На швидкість мережі вони не впливають.

Словник

Термін Що це
VPC ваша ізольована мережа в AWS
NAT Gateway шлюз для виходу приватних серверів в інтернет
Stateful відповідь на дозволений запит дозволена автоматично
Peering пряме з'єднання двох VPC
Gateway endpoint приватний шлях до S3 і DynamoDB
Interface endpoint приватний шлях до інших сервісів через ENI
Direct Connect фізичний канал до AWS без інтернету
Flow Logs журнали мережевого трафіку

Що запам'ятати на іспит

  1. SG: stateful, лише allow, на сервері. NACL: stateless, allow і deny, на підмережі.
  2. Заблокувати IP можна лише в NACL.
  3. NAT Gateway у публічній підмережі з Elastic IP: тільки вихід.
  4. Peering не транзитний.
  5. S3 і DynamoDB: gateway endpoint. Інше: interface endpoint.
  6. VPN: IPsec через інтернет. Direct Connect: фізичний канал.
  7. Flow Logs: у CloudWatch Logs, S3 або Firehose.

Перевірте себе

  1. Чим stateful відрізняється від stateless?
  2. Що потрібно приватному серверу, щоб скачати оновлення?
  3. Чому peering не дає A з C?
  4. Куди можна надіслати Flow Logs?
Відповіді
  1. Stateful сам дозволяє відповідь, stateless потребує окремого правила.
  2. NAT Gateway у публічній підмережі.
  3. Peering не підтримує транзитний трафік.
  4. CloudWatch Logs, S3, Amazon Data Firehose.
