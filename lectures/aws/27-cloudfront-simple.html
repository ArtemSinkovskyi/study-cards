Лекція 27: CloudFront, CDN

Середній рівень: усі правила з повної лекції, але простими словами. Повна: ../27-cloudfront.md. Усе звірено з документацією AWS; що не підтверджено, позначено (не звірено). В AWS це не виконували.

Головна ідея

CloudFront тримає копії ваших файлів у точках по світу, ближче до користувача. Перший запит іде до оригіналу (origin), наступні віддаються з кешу. Швидше, дешевше для origin і безпечніше.

Навіщо це так задумано

Якщо сервер в Європі, користувач в Австралії чекає довго. Копія поруч віддається миттєво. Мережа по світу ще й захищає від DDoS разом зі Shield і WAF.

Крок 1. Словник

Термін Суть
Edge location точка по світу, де лежить кеш
Origin де лежить оригінал: S3, ALB, EC2, будь-який HTTP
Cache key за чим кеш розпізнає об'єкт
TTL скільки об'єкт живе в кеші
OAC спосіб CloudFront ходити в приватний S3
Signed URL / cookie підписаний доступ до платного контенту

Крок 2. Як це працює

  1. Користувач просить файл.
  2. Запит іде на найближчий edge.
  3. Є в кеші: віддають одразу. Немає: CloudFront бере з origin, кладе в кеш і віддає.

Крок 3. Origins

Origin Коли
S3 bucket роздавати файли, також завантажувати в S3 через CloudFront; закритий OAC
VPC origin застосунок у приватній підмережі: ALB, NLB, EC2 (деталі не звірено)
Custom origin S3 як сайт, будь-який публічний HTTP

Пастка: S3 website endpoint це custom origin, OAC для нього не працює. Різні origins за шляхом: /images/* на S3, /api/* на ALB, /* решта.

OAC краще за старий OAI: підтримує всі регіони, SSE-KMS і PUT/DELETE.

Крок 4. Cache key і політики

Ключ кешу за замовчуванням: ім'я сайту плюс шлях. Можна додати заголовки, cookie, query через cache policy. Чим менше в ключі, тим більше влучань у кеш.

  • Cache policy: що входить у ключ і скільки живе.
  • Origin request policy: що передати на origin, не додаючи до ключа.

Крок 5. Скільки живе об'єкт, рецепт у 3 кроки

  1. Подивись, чи origin дав max-age (чи s-maxage).
  2. Обмеж значення знизу Minimum TTL, зверху Maximum TTL.
  3. Якщо заголовка нема, бери Default TTL (24 години, якщо не змінено).

Приклад: Min 60, Max 3600, origin дав max-age=86400. Результат 3600.

Додатково: CloudFront ігнорує Cache-Control у запиті користувача, тому він не може примусити взяти з origin.

Крок 6. Geo restriction

  • Allowlist: пускати лише зі списку країн.
  • Blocklist: не пускати зі списку.
  • Заборонених відсікає з кодом 403. Діє на весь distribution. Якщо країну визначити не вдалося, контент віддається.

Крок 7. Платний контент

  • Signed URL: один файл.
  • Signed cookies: багато файлів, URL звичайний.
  • Підпис містить термін дії, за потреби дату початку й діапазон IP; хто може підписувати, задає trusted key group у distribution.
таблицю можна гортати вбік →
CloudFront signed URL S3 presigned URL
Від чийого імені за шляхом, незалежно від origin від імені того, хто підписав
Кеш працює напряму в S3, повз кеш
Ключі trusted key group IAM-ключ

У нотатках було «ключі лише root». Це застаріле: зараз рекомендують trusted key groups, root не потрібен.

Крок 8. Origin groups

Дві адреси: основна (primary) і запасна (secondary). Якщо основна повернула помилку з вибраних кодів чи не відповіла, CloudFront йде на запасну. Працює лише для методів GET, HEAD і OPTIONS. Коди на вибір: 400, 403, 404, 416, 429, 500, 502, 503, 504; збій підключення відповідає коду 503, таймаут 504 (їх теж треба вибрати). Типово чекає primary до 30 секунд (3 спроби по 10).

Крок 9. Real-time logs

Журнали запитів за секунди надходять у Kinesis Data Streams. Можна вибрати відсоток запитів (sampling rate), поля й шляхи. Це платно й за принципом best effort.

Що запам'ятати на іспит

  1. Приватний S3 за CDN: OAC. S3 website лише custom origin.
  2. Cache key: ім'я плюс шлях; менше в ключі, більше hit ratio.
  3. Origin request policy передає, але не додає до ключа.
  4. TTL: Min, Default (24 год), Max разом із заголовками origin.
  5. Geo restriction: allowlist чи blocklist, 403, на весь distribution.
  6. Signed cookies для багатьох файлів. Trusted key groups, не root.
  7. Origin group: GET, HEAD, OPTIONS.
  8. Real-time logs у Kinesis Data Streams.
