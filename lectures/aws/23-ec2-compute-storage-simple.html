Лекція 23: EC2, типи, режими купівлі й диски

Середній рівень: усі правила й числа з повної лекції, але простими словами. Повна: ../23-ec2-compute-storage.md. Усе звірено з документацією AWS; що не підтверджено, позначено (не звірено). В AWS це не виконували.

Головна ідея

EC2 це віртуальний сервер. Іспит питає три речі: який тип обрати, як дешевше за нього заплатити і де зберігати дані. Для кожної є коротке правило.

Навіщо це так задумано

Навантаження бувають різні: одному потрібен процесор, іншому пам'ять, третьому швидкий диск. Тому AWS продає різні типи. Платити за годину завжди дорого, тому є режими купівлі: хочеш гарантію платиш більше, хочеш дешево погоджуєшся, що сервер можуть забрати. Диски теж різні за швидкістю й тривалістю життя.

Крок 1. Словник

Термін Суть

AMI шаблон, з якого запускається сервер
EBS мережевий диск для EC2, живе в одній AZ

EFS спільна папка для багатьох серверів (NFS)

Крок 2. П'ять типів інстансів

Сімейство Коли
General Purpose усього потроху: застосунки, ігри, бекенд, малі бази
Compute Optimized потрібен сильний процесор

Крок 3. Як заплатити

Режим Суть однією фразою
On-Demand платиш за секунди роботи (мінімум 60 с), без зобов'язань
Reserved Instance 1 або 3 роки, знижка за ту саму конфігурацію
Savings Plans 1 або 3 роки, зобов'язання на суму в USD за годину, до 72% знижки
Spot дешево, але сервер можуть забрати, за 2 хвилини попередять
Dedicated Host цілий фізичний сервер ваш, для ліцензій на ПЗ
Dedicated Instance окреме залізо, оплата за годину
Capacity Reservation гарантоване місце в конкретній AZ

Як обирати за формулюванням:

  • «Тестування, непередбачуваний трафік» → On-Demand.
  • «Стале навантаження три роки» → Reserved або Savings Plans.
  • «Хочу гнучкість у типах і регіонах» → Savings Plans (Reserved не гнучкий).
  • «Big data, переживе перерву» → Spot.
  • «Ліцензія прив'язана до фізичного сервера» → Dedicated Host.
  • «Reserved Instance з можливістю обміну» → Convertible (Standard лише змінюється).

Reserved Instance не фізичний сервер, а знижка в рахунку. Після закінчення терміну сервер працює далі, але вже за ціною On-Demand.

Крок 4. EBS

EBS підключається до сервера мережею, живе в одній AZ і не зникає, коли сервер зупинено. Типи:

Тип Коротко
gp3 / gp2 SSD загального призначення, баланс ціни й швидкості; gp3 до 80 000 IOPS
io2 / io1 SSD з гарантованими IOPS для баз; io1 до 64 000, io2 Block Express до 256 000 IOPS
st1 HDD для великих потоків даних, логів, big data
sc1 HDD найдешевший, для архівів і рідкісних даних

Правила:

  • SSD для малих випадкових операцій (IOPS), HDD для великих потокових (throughput).
  • HDD не може бути boot-диском.
  • Multi-Attach: один io1 чи io2 диск до 16 серверів в одній AZ. gp2/gp3 так не вміють. Потрібна кластерна файлова система.
  • Звичайно один диск підключено до одного сервера.
  • Знімок (snapshot) дозволяє створити диск в іншій AZ.
  • Випадково видалений snapshot повертають з Recycle Bin, якщо в ньому було правило зберігання.

Крок 5. Instance Store

Це диск прямо в фізичному сервері. Дуже швидкий, але:

  • при reboot дані лишаються;
  • при stop, hibernate і terminate дані зникають.

Тому там тримають лише кеші й тимчасові дані.

Крок 6. EFS

Спільна файлова система для багатьох серверів одночасно (NFS). Доступна з EC2, контейнерів і Lambda. Regional зберігає дані в кількох AZ. Windows-інстанси її не підтримують. Дорожча за EBS, але має дешевші рівні зберігання (не звірено).

Крок 9. Метадані

Застосунок на сервері бере з 169.254.169.254 дані про сам сервер: ID, AZ, тимчасові ключі ролі. Спершу PUT за токеном (IMDSv2). У user data не кладіть паролі: їх бачить будь-яка програма на сервері.

Що запам'ятати на іспит

  1. Гнучкість за типом і регіоном: Savings Plans. Знижка до 72%.
  2. Spot: попередження за 2 хвилини. Для задач, що переживають перерву.
  3. Dedicated Host для ліцензій на фізичний сервер, Dedicated Instance оплата за годину.
  4. EBS в одній AZ. Multi-Attach лише io1/io2, до 16 серверів, одна AZ.
  5. HDD (st1, sc1) не бувають boot.
  6. Instance Store: reboot переживає, stop ні.
  7. EFS: багато серверів, Linux, кілька AZ.
  8. Порт 22: SSH і SFTP. 3389: RDP. 21: FTP.
