Лекція 15: CloudFormation

Середній рівень: усі правила з повної лекції, але простими словами. Повна: ../15-cloudformation.md. Що не звірено з документацією, позначено (не звірено).

Головна ідея

CloudFormation створює ресурси AWS за описом (шаблоном): ви пишете, що хочете, а сервіс сам вирішує порядок і виконує. Набір створених ресурсів називається стеком. Видалили стек, зникли й ресурси (якщо не сказано інакше).

Навіщо це так задумано

Ручне клікання в консолі не повторити й не перевірити. Шаблон лежить у Git, його переглядають, як код, і з нього можна відтворити всю інфраструктуру.

Крок 1. Словник

Термін Суть

Крок 2. Як передати шаблон

  • напряму до 51 200 байт;
  • через S3 URL до 1 МБ.

Старий шаблон не редагують: завантажують нову версію й оновлюють стек. У стека є унікальне ім'я.

Крок 3. Розділи шаблону

  • Mappings: фіксовані значення прямо в шаблоні. Приклад: який AMI брати в якому регіоні, або розміри для dev і prod.
  • Outputs: що стек «віддає назовні». Якщо додати Export, інший стек зможе взяти значення. Типово: мережевий стек віддає VPC ID й Subnet IDs, а стек застосунку їх бере. Це найкращий спосіб співпраці між стеками.
  • Conditions: створювати ресурс чи вихід лише якщо умова істинна (середовище, регіон, значення параметра). Функції: Fn::And, Equals, If, Not, Or.

Крок 4. Вбудовані функції

Функція Що дає
!Ref для параметра його значення, для ресурсу його physical ID (наприклад id EC2)
!GetAtt атрибут ресурсу (наприклад зона доступності інстансу)
!FindInMap [Map, Ключ1, Ключ2] значення з mapping
!ImportValue значення, експортоване іншим стеком
Fn::Base64 рядок у Base64 (для UserData EC2)

Крок 5. Що стається при збої

Що впало Що відбудеться
Створення стеку усе створене видаляється (можна вимкнути відкат, щоб розібратися)
Оновлення стеку автоматичний відкат до останнього робочого стану
Сам відкат виправити ресурси вручну й викликати ContinueUpdateRollback

Крок 6. Service role і capabilities

  • Service role: CloudFormation діє від її імені. Користувач може керувати стеком, не маючи прав на ресурси стеку. Йому потрібне право iam:PassRole. Так дотримуються найменших привілеїв.
  • CAPABILITY_IAM: потрібна, коли шаблон створює IAM-ресурси. CAPABILITY_NAMED_IAM, якщо вони з власними іменами.
  • CAPABILITY_AUTO_EXPAND: коли в шаблоні макроси (зокрема AWS::Serverless), а стек створюють напряму без change set. Самі вкладені стеки її не вимагають, лише макроси разом із вкладеними.
  • Без потрібної згоди: InsufficientCapabilitiesException.

Крок 7. Три захисти, які легко сплутати

Захист Від чого
DeletionPolicy що зробити з ресурсом при видаленні стеку: Delete (за замовчуванням), Retain (залишити), Snapshot (знімок перед видаленням)
Stack Policy від змін ресурсів під час оновлення; після її задання все захищено, потрібен явний Allow; Deny сильніший
Termination Protection від випадкового видалення самого стеку

Пастки:

  • Delete не видалить непорожній S3 bucket.
  • За замовчуванням для AWS::RDS::DBCluster (і DBInstance без кластера) діє Snapshot, а не Delete.
  • Stack policy не можна видалити, лише змінити.

Крок 8. Custom resources

Для ресурсів, яких CloudFormation ще не вміє, або для власної логіки (Lambda на create/update/delete). Обовʼязкова властивість ServiceToken: ARN Lambda чи SNS у тому ж регіоні. Приклад: Lambda очищує S3 bucket перед видаленням стеку.

Крок 9. StackSets

Один шаблон розгортається в кількох акаунтах і регіонах однією операцією; оновлення StackSet оновлює всі stack instances. Можна на всю AWS Organization. Створити може лише адмін-акаунт (чи delegated administrator).

Словник

Термін Що це
Stack група ресурсів, створена з шаблону
Export / ImportValue віддати значення зі стеку й взяти в іншому
ContinueUpdateRollback дотиснути відкат, що застряг
Capability підтвердження, що ви згодні на створення IAM чи використання макросів
Stack Policy захист ресурсів від змін при оновленні

DeletionPolicy
  • рівень: ресурс

  • знімають зміною шаблону
Stack Policy
  • рівень: ресурс
  • від змін і заміни під час оновлення
  • знімають зміною політики, видалити не можна
Termination Protection
  • рівень: стек
  • від видалення самого стека
  • знімають вимкненням прапорця
DeletionPolicy: що з ресурсом
ЗначенняЩо робить

Не діє, коли ресурс замінюється під час оновлення. Delete не спрацює для непорожнього S3 bucket. Типово Snapshot для RDS::DBCluster і для DBInstance без DBClusterIdentifier.

Що запам'ятати на іспит

  1. Шаблон: напряму до 51 200 байт, через S3 до 1 МБ.
  2. Ref для параметра: значення, для ресурсу: physical ID.
  3. Створення впало: усе видаляється. Оновлення впало: автовідкат. Відкат впав: ContinueUpdateRollback.
  4. IAM у шаблоні: CAPABILITY_IAM або CAPABILITY_NAMED_IAM; без них InsufficientCapabilitiesException.
  5. Макроси (чи макроси з вкладеними стеками): CAPABILITY_AUTO_EXPAND.
  6. DeletionPolicy Delete не видаляє непорожній S3.
  7. Stack policy захищає від оновлень; termination protection від видалення стеку.
  8. Custom resource: ServiceToken обовʼязковий, у тому ж регіоні.
  9. StackSets: лише з адмін-акаунта.

Перевірте себе

  1. Як дозволити користувачу створювати стек без прав на його ресурси?
  2. Яка capability потрібна для IAM-ролі з власним ім'ям?
  3. Як видалити стек із непорожнім S3 bucket?
  4. Що робить Fn::ImportValue?
  5. Створення стеку впало. Що буде за замовчуванням?
  6. Чим stack policy відрізняється від termination protection?
Відповіді
  1. Service role та iam:PassRole для користувача.
  2. CAPABILITY_NAMED_IAM.
  3. Спершу очистити (наприклад custom resource з Lambda), бо Delete не видаляє непорожній bucket.
  4. Бере значення, експортоване іншим стеком.
  5. Усе створене видаляється.
  6. Stack policy захищає ресурси від змін при оновленні, termination protection захищає сам стек від видалення.
