Лекція 13: KMS, секрети, сертифікати

Середній рівень: усі правила й числа з повної лекції, але простими словами. Повна: ../13-kms-secrets-certificates.md. Факти, які в повній лекції позначено «з пам'яті», тут із позначкою (не звірено).

Головна ідея

KMS зберігає ключі шифрування й виконує операції з ними. Ключ ніколи не покидає KMS. Ви не виносите ключ, а приносите дані, і KMS шифрує їх у себе.

Security це 26% іспиту, і шифрування тут важливе.

Навіщо це так задумано

Ключі шифрування не тримають біля даних: їх береже окремий сервіс із журналом, а дані шифрують одноразовим ключем. Секрети виносять із коду, щоб їх можна було міняти без нового деплою.

Крок 1. Три типи ключів

Тип Хто керує CloudTrail Плата за ключ

Якщо питання про контроль, ротацію за своїм графіком чи доступ з іншого акаунта, відповідь customer managed. З alias/aws/s3 чи alias/aws/sqs доступ іншому акаунту не дати, бо політику не змінити.

Крок 2. Envelope encryption

Encrypt приймає до 4 КБ. Файл на 10 МБ напряму не зашифрувати. Тому:

  1. GenerateDataKey повертає відкритий ключ даних і його ж зашифровану копію.
  2. Ви шифруєте дані локально відкритим ключем і стираєте його.
  3. Зберігаєте шифротекст і зашифрований ключ разом.
  4. Для читання: Decrypt на зашифрований ключ, далі розшифровуєте локально.

Переваги: швидко (дані не їдуть у KMS), дешево, будь-який розмір. AWS Encryption SDK робить це за вас і може кешувати ключі даних.

Запам'ятайте пару: GenerateDataKey для шифрування файлу, Encrypt/Decrypt для маленьких секретів до 4 КБ. GenerateDataKeyWithoutPlaintext віддає лише зашифрований ключ, для системи, що шифруватиме пізніше.

Також існує encryption context: додаткові дані, прив'язані до шифрування. Без них розшифрувати не вийде.

Крок 3. Політики ключів: головна пастка

Кожен ключ має рівно одну key policy, і без неї IAM не працює. IAM-політика з kms:Decrypt не має ефекту, якщо key policy не дозволяє IAM. Типова key policy це дозволяє рядком для root акаунта. Навіть root не має прав, якщо їх не дано явно.

Між акаунтами потрібні обидва боки: key policy в акаунті ключа дозволяє інший акаунт, а IAM-політика в іншому акаунті дозволяє своєму користувачу. Жодного з двох боків недостатньо.

Key policy регіональна. Grants дають тимчасовий програмний доступ, ними користуються сервіси AWS.

Діагностика. AccessDenied з kms:Decrypt у S3 означає, що користувач має s3:GetObject, але не має права на ключ. Для читання об'єкта SSE-KMS потрібні обидва дозволи.

Крок 4. Ротація

Значення
Автоматична ротація customer managed, період 90-2 560 днів
Ротація на вимогу RotateKeyOnDemand, до 10 разів на ключ
Імпортований матеріал лише на вимогу
Не ротується асиметричні ключі, HMAC, CloudHSM custom key store

Головне: після ротації старі дані лишаються читабельними, бо KMS зберігає старий матеріал, а key id не змінюється. Застосунок нічого не помічає.

Видалення ключа має 7-30 днів очікування (за замовчуванням 30), його можна скасувати. Після видалення дані втрачено назавжди. Тому спершу DisableKey, подивіться на помилки, потім видаляйте.

Multi-Region keys: primary реплікується в інші регіони, той самий ключ розшифровує дані в кожному.

Крок 5. S3 і KMS: Bucket Key

Без нього S3 викликає KMS на кожен об'єкт, а виклики платні й мають ліміт. S3 Bucket Key зменшує витрати на запити KMS до 99%: S3 бере короткоживучий ключ рівня бакета й сам робить ключі даних.

Наслідки:

  • encryption context і записи CloudTrail показують ARN бакета, а не об'єкта, тож політики, що фільтрують за ARN об'єкта, зламаються;
  • у CloudTrail менше подій;
  • уже наявні об'єкти не змінюються, потрібен CopyObject;
  • не працює з DSSE-KMS.

Якщо Lambda читає й пише в бакет із SSE-KMS, їй потрібні kms:Decrypt для читання й kms:GenerateDataKey для запису. Без них AccessDenied. Примусити шифрування можна bucket policy з Deny на s3:PutObject, якщо заголовок x-amz-server-side-encryption не aws:kms (не звірено).

Питання Відповідь
Дані не мають бачити навіть AWS client-side (Encryption SDK, DynamoDB Encryption Client)
Аудит доступу до ключа SSE-KMS і CloudTrail

Шифрування при передачі TLS; bucket policy з aws:SecureTransport: false і Deny

Крок 7. Secrets Manager проти Parameter Store

Secrets Manager Parameter Store
Для чого паролі БД, API-ключі конфігурація й секрети
Ротація автоматична (нативно RDS, DocumentDB, Redshift) нема

Вибір: потрібна ротація, значить Secrets Manager. Просто конфіг чи дешево, значить Parameter Store. CloudFormation читає обидва динамічними посиланнями {{resolve:secretsmanager:...}} і {{resolve:ssm:...}} (не звірено).

Крок 8. Сертифікати (ACM)

  • публічні сертифікати безкоштовні для інтегрованих сервісів (ELB, CloudFront, API Gateway);
  • автооновлення починається до 60 днів до закінчення й працює з DNS-валідацією, якщо CNAME лишився;
  • сертифікат має бути в тому ж регіоні, що й ресурс. Виняток: CloudFront лише в us-east-1;
  • AWS Private CA це власний центр для внутрішніх сервісів, платиться щомісяця;
  • імпортований сертифікат сам не оновлюється.

Для розробки SSH-ключі генерують ssh-keygen чи aws ec2 create-key-pair, а TLS-сертифікат для тестів openssl (не звірено).

Крок 9. Чутливі дані (PII, PHI)

  • Amazon Macie шукає персональні дані (PII) та інші чутливі дані в S3.
  • CloudWatch Logs data protection маскує чутливі дані в логах (політики на рівні акаунта чи лог-групи); сирі значення бачать лише ті, хто має logs:Unmask.
  • У коді не логуйте сирі дані. Powertools Logger вміє маскувати.
  • Логи це частий канал витоку (див. лекцію 21).

Що запам'ятати на іспит

  1. Encrypt до 4 КБ, для файлів GenerateDataKey і envelope encryption.
  2. Key policy обов'язкова. Без неї IAM не діє. Між акаунтами потрібні обидва боки.
  3. Для читання SSE-KMS потрібні s3:GetObject і kms:Decrypt.
  4. Ротація не ламає старі дані. Видалення ключа через 7-30 днів.
  5. Bucket Key дає до 99% менше запитів, але CloudTrail показує бакет.
  6. Ротація секрету: Secrets Manager. Конфіг: Parameter Store.
  7. Сертифікат для CloudFront лише в us-east-1.

Перевірте себе

  1. Чому файл на 10 МБ не зашифрувати через Encrypt?
  2. Опишіть кроки envelope encryption.
  3. У користувача є kms:Decrypt в IAM, але AccessDenied. Чому?
  4. Що станеться зі старими даними після ротації?
  5. Ключ випадково видалили вчора. Що робити?
  6. Що зламається в політиках після ввімкнення Bucket Key?
  7. Коли Secrets Manager, а коли Parameter Store?
  8. Де створити сертифікат для CloudFront і для ALB в eu-north-1?
Відповіді
  1. Encrypt приймає до 4 КБ.
  2. GenerateDataKey, шифруєте локально, зберігаєте разом шифротекст і зашифрований ключ, Decrypt ключа для читання.
  3. Key policy не дозволяє IAM або не дозволяє цього користувача.
  4. Лишаються читабельними.
  5. Якщо ще в очікуванні видалення (7-30 днів), скасувати видалення.
  6. Політики, що фільтрують за ARN об'єкта.
  7. Ротація потрібна: Secrets Manager. Просто конфіг чи дешево: Parameter Store.
  8. CloudFront: us-east-1. ALB: у eu-north-1.
