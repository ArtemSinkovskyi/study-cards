Лекція 21: AI-сервіси AWS і безпека

Середній рівень: усі правила з повної лекції, але простими словами. Повна: ../21-ai-services-security.md. Факти, які в повній лекції позначено «з пам'яті», тут із позначкою (не звірено).

Головна ідея

Цей розділ нове в C03 (навичка 2.3 «AI security»). Іспит перевіряє не «як побудувати AI», а «як підключити й захистити».

Поза межами іспиту (за Exam Guide): вибір моделей, prompt engineering, проєктування RAG, проєктування guardrails та AI-governance. Також поза межами: Amazon Rekognition, Polly, SageMaker AI, Strands Agents, Quick Sight. Правильна відповідь на питання про AI майже завжди стосується Bedrock.

Увага: Quick Sight поза іспитом, а Amazon Quick у списку in-scope. Це різні позиції.

Навіщо це так задумано

Модель приймає довільний текст і сама вирішує, що робити, тому потрібні фільтри на вході й виході та мінімальні права: помилки моделі наперед не передбачити.

Крок 1. Виклик Bedrock

Два API:

API Для чого
Converse єдиний формат для різних моделей
InvokeModel формат конкретної моделі

Обидва мають варіанти зі стрімінгом (ConverseStream, InvokeModelWithResponseStream).

  • Lambda потребує bedrock:InvokeModel (ця дія покриває й Converse); у Resource вказують ARN моделі виду arn:aws:bedrock:<регіон>::foundation-model/<model-id> (поле акаунта порожнє).
  • Тротлінг дає ThrottlingException: повторювати з backoff.
  • Довгі виклики не вкладаються в timeout Lambda за замовчуванням 3 с: підвищте timeout.
  • У ConverseCommand можна задати inferenceConfig (наприклад, maxTokens) і guardrailConfig.

Крок 2. Доступ

  • доступ до Bedrock дається через IAM: хто може викликати яку модель;
  • обмежуйте Resource конкретними моделями;
  • окремі ролі для застосунку й для розробників;
  • використання відстежується в CloudTrail.

Крок 3. Приватність

Зі сторінки Bedrock: вміст «не використовується для покращення базових моделей і не передається провайдерам моделей». Вхідні й вихідні дані не використовуються для тренування моделей Amazon чи сторонніх. Це головна відповідь на питання «чи вчиться модель на наших даних».

Приватне з'єднання: AWS PrivateLink (interface VPC endpoint) дає доступ до Bedrock без публічного інтернету. Питання «дані не мають іти через інтернет» означає interface VPC endpoint.

Шифрування: дані в передачі шифруються TLS. Власний ключ KMS можна задати для custom models (customModelKmsKeyId) і для агентів (customerEncryptionKeyArn); для guardrails джерела розходяться (не звірено).

Крок 4. Guardrails

таблицю можна гортати вбік →
Фільтр Що робить Приклад
Content filters шкідливий зміст: Hate, Insults, Sexual, Violence, Misconduct, Prompt Attack блокувати образи
Denied topics заборонені теми інвестпоради в банку
Word filters слова, фрази назви конкурентів
Sensitive information filters блокує чи маскує PII, свої regex маскувати SSN
Contextual grounding відповідь не спирається на джерело галюцинації в RAG
Automated Reasoning перевірка логічними правилами правила полісу

Як працюють:

  • фільтрують і вхід, і вихід;
  • підключаються до виклику моделі (ID і версія) або окремо через ApplyGuardrail, навіть для сторонніх моделей;
  • спершу робоча чернетка, далі версія;
  • тегами можна перевіряти лише частину запиту: тільки ввід користувача, не системні інструкції.

Мапа питань іспиту:

Потреба Фільтр
прибрати номери карток sensitive information (mask)
не обговорювати конкурентів word filter чи denied topic
захист від «ігноруй інструкції» content filter: Prompt Attack
модель вигадує contextual grounding

Важливо: guardrail не замінює авторизацію. Модель не має мати прав більше, ніж потрібно.

Крок 5. Безпека агентів

Агент сам викликає інструменти. Ризики й рішення:

Ризик Рішення
агент робить зайве tool-use authorization: лише дозволені інструменти, мінімальні права
дані одного користувача в сесії іншого session isolation
небезпечна дія (видалити, оплатити) human-in-the-loop схвалення
непряме впорскування через документ чи сайт вміст інструмента це дані, а не команди; фільтри

AgentCore:

Компонент Що робить
Runtime безсерверний запуск агентів, справжня ізоляція сесій
Memory коротка й довга пам'ять
Gateway перетворює API й Lambda на MCP-інструменти
Identity ідентичність агента, сумісна з Cognito, Okta, Auth0
Policy детерміновані правила на кожен виклик інструмента
Observability трасування кроків через OpenTelemetry
Code Interpreter, Browser ізольовані пісочниці
Evaluations, Registry, Harness оцінка, каталог, готовий цикл агента

Зв'язок із навичками: Policy означає tool-use authorization, Runtime означає session isolation, Identity означає хто діє.

Bedrock Agents це простіший керований варіант. AWS радить AgentCore, якщо потрібен будь-який фреймворк чи більше контролю.

Крок 6. Логи

Логи часто містять промпти з PII. Заходи:

  • Model invocation logging Bedrock (CloudWatch Logs чи S3 того ж акаунта й регіону) вимкнений за замовчуванням, вмикається окремо; вміст логуйте свідомо;
  • маскування: CloudWatch Logs data protection;
  • мінімальні права на групи логів, шифрування KMS, короткий retention;
  • Guardrails логують порушення в CloudWatch або S3;
  • метрики токенів є в CloudWatch.

Логуйте метадані (модель, токени, вартість), а не повний промпт.

Крок 7. AI-інструменти розробника

Kiro це AI-середовище зі спільним агентом для IDE, CLI, Web і Mobile:

  • Specs: requirements, design, tasks; окремий bugfix spec;
  • Steering: правила проєкту для агента;
  • Hooks: автоматичні дії при зміні файла чи завершенні задачі;
  • MCP: підключення зовнішніх інструментів;
  • є міграція з Amazon Q Developer і Q CLI.
Навичка Де застосувати
1.1.9 код, огляд, сканування spec-driven генерація, автоматичний code review
3.2.5 тести генерація тестів, аналіз результатів
3.3.9 CI/CD затвердження деплою, перевірка після нього
4.1.5 відлагодження аналіз помилок, пропозиції виправлень
4.3.6 оптимізація пошук вузьких місць

Пастка: згенерований AI код перевіряють як звичайний: тести, огляд, сканування.

Amazon Quick це інструмент для бізнес-користувачів, не для розробки (з вторинних джерел, офіційно не підтверджено).

Що запам'ятати на іспит

  1. Bedrock: Converse це єдиний формат, дані не тренують моделі.
  2. Приватність: PrivateLink. Доступ: IAM. Аудит: CloudTrail.
  3. Guardrails фільтрують вхід і вихід. PII це sensitive information. Prompt injection це Prompt Attack. Галюцинації це grounding.
  4. ApplyGuardrail працює без виклику моделі, навіть для сторонніх моделей.
  5. Агенти: мінімум прав, ізоляція сесій, людина для небезпечних дій.
  6. Логи не мають містити PII.
  7. Вибір моделей і prompt engineering на іспиті не перевіряють.

Перевірте себе

  1. Як не пускати дані до Bedrock через інтернет?
  2. Клієнт питає, чи вчиться модель на його даних. Що відповісти?
  3. Який фільтр замаскує PII у відповіді?
  4. Який фільтр захищає від prompt injection?
  5. Як застосувати guardrail до моделі поза Bedrock?
  6. Модель у RAG вигадує факти. Який фільтр?
  7. Агент хоче видалити базу. Що має зупинити дію?
  8. Де логувати виклики моделі, щоб не злити PII?
Відповіді
  1. Interface VPC endpoint (AWS PrivateLink).
  2. Ні: вміст не використовується для покращення базових моделей і не передається провайдерам.
  3. Sensitive information filter (mask).
  4. Content filter «Prompt Attack».
  5. ApplyGuardrail.
  6. Contextual grounding.
  7. Human-in-the-loop схвалення й tool-use authorization (мінімальні права).
  8. Логувати метадані (модель, токени, вартість), маскувати чутливі дані, обмежити доступ до логів.
