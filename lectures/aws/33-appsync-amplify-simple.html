Лекція 33: AppSync і Amplify

Середній рівень: усі правила з повної лекції, але простими словами. Повна: ../33-appsync-amplify.md. Факти звірено з документацією AWS (AppSync, Amplify Hosting); що не звірено, позначено (не звірено). В AWS це не виконувалось.

Головна ідея

AppSync це керований GraphQL: клієнт сам просить потрібні поля й отримує рівно їх, навіть з кількох джерел. Amplify це набір інструментів для веб- і мобільних застосунків: автентифікація, дані, хостинг.

Для іспиту: AppSync обирають, коли треба гнучкі запити, real-time і офлайн-синхронізація; Amplify, коли треба швидко зібрати фронтенд з бекендом і CI/CD.

Навіщо це так задумано

У звичайному REST-ендпоінті клієнт отримує фіксований набір полів і часто робить кілька запитів. GraphQL дозволяє попросити все потрібне за один запит. Amplify вирішує інше: щоб не збирати вручну Cognito, DynamoDB і хостинг, ви кажете, що треба, а AWS розгортає ресурси.

Крок 2. AppSync: як це працює

  1. Ви завантажуєте в AppSync одну схему GraphQL.
  2. До полів схеми підключаєте resolvers: DynamoDB, Aurora, OpenSearch, Lambda (для чого завгодно), HTTP (публічні API).
  3. Клієнт шле запит із потрібними полями й отримує JSON саме з ними. Дані з кількох джерел можна зібрати в одну відповідь.

Ще AppSync вміє:

  • real-time через WebSocket (у чужому конспекті ще «MQTT поверх WebSocket», не звірено);
  • для мобільних застосунків: локальні дані й синхронізація, тобто офлайн;
  • метрики й логи в CloudWatch.

Крок 3. Авторизація в AppSync

У чужому конспекті чотири способи, за документацією п'ять:

Тип Суть
API_KEY простий варіант для неавтентифікованого API, контролює throttling; заголовок x-api-key; до 365 днів, можна продовжити
AWS_IAM користувачі й ролі IAM, cross-account; дія appsync:GraphQL
OPENID_CONNECT провайдер OIDC, токен JWT
AMAZON_COGNITO_USER_POOLS Cognito, можна обмежувати за групами
AWS_LAMBDA ваша Lambda вирішує, чи пускати

Один режим основний, інші додаткові; для окремих полів є директиви @aws_api_key, @aws_iam, @aws_oidc, @aws_cognito_user_pools, @aws_lambda.

Власний домен і HTTPS: у конспекті радять ставити CloudFront перед AppSync. Чи є зараз вбудований custom domain, не перевірено (не звірено).

Крок 4. Amplify

Amplify це «Elastic Beanstalk для веб- і мобільних застосунків»: даєте опис, а AWS розгортає ресурси. Є готові функції (автентифікація, сховище даних, файли, ML) і бібліотеки компонентів для React, Vue, JavaScript, iOS, Android, Flutter.

Створюють бекенд через Amplify CLI або Amplify Studio. Це підхід Gen 1; в Gen 2 бекенд описують кодом на TypeScript.

таблицю можна гортати вбік →
Команда Що стоїть за нею Що дає
amplify add auth Cognito реєстрація, вхід, MFA, social sign-in, готовий UI
amplify add api AppSync + DynamoDB локальні дані з автосинхронізацією в хмару, GraphQL, офлайн і real-time

(Чи DataStore лишається в актуальній документації, не звірено.)

Крок 5. Amplify Hosting

Хостинг із Git: пушите, а Amplify збирає й розгортає на CDN.

Можливість Що це
CI/CD збірка, тест, розгортання
Pull request previews перегляд змін до злиття
Custom domains власний домен
Monitoring моніторинг
E2E testing наскрізні тести до продакшену
Feature branches гілка дає середовище
Password protection, redirects, atomic deployments закрита гілка, редіректи, оновлення лише після повного розгортання

E2E-тести: у amplify.yml є крок test. Він має фази preTest (встановити залежності, запустити застосунок), test (тут запускається Cypress) і postTest (прибрати), та artifacts (звіти, скриншоти, відео). Cypress формує UI-звіт.

Рецепт «як потрапляє в прод» (3 кроки): 1) push у гілку; 2) збірка, потім фаза test з Cypress; 3) якщо тест упав, регресію зупинено до продакшену, якщо пройшов, розгортання.

Що запам'ятати на іспит

  1. AppSync це GraphQL: схема, resolvers, джерела DynamoDB, Aurora, OpenSearch, Lambda, HTTP.
  2. AppSync дає real-time (WebSocket) і офлайн-синхронізацію для мобільних.
  3. Авторизація AppSync: API_KEY, AWS_IAM, OPENID_CONNECT, AMAZON_COGNITO_USER_POOLS, AWS_LAMBDA.
  4. amplify add auth це Cognito; amplify add api це AppSync + DynamoDB.
  5. Amplify Hosting: CI/CD, PR preview, домени, моніторинг, E2E (Cypress) у фазі test файла amplify.yml.
  6. Для фіксованого REST з usage plans: API Gateway, не AppSync.

Перевірте себе

  1. Яка перевага GraphQL над фіксованим REST-ендпоінтом?
  2. З чого починається AppSync і що робить resolver?
  3. Мобільному застосунку потрібні офлайн-дані. Який сервіс?
  4. Яку Lambda-подібну авторизацію конспект забув у AppSync?
  5. Які сервіси стоять за amplify add auth і amplify add api?
  6. Де запускаються E2E-тести в Amplify Hosting?
Відповіді
  1. Клієнт сам обирає поля й отримує лише їх, з кількох джерел за один запит.
  2. Із завантаження схеми; resolver зв'язує поле схеми з джерелом даних.
  3. AppSync (або Amplify на його основі).
  4. AWS_LAMBDA: власна Lambda вирішує, чи пускати запит.
  5. Cognito і AppSync плюс DynamoDB.
  6. У фазі test файла amplify.yml, з Cypress.
