🖼 ECS: контейнери, tasks, services

Від образу до сервісу
Docker image: створюєш образ
↓
ECR: сховище образів (замість Docker Hub), public чи private
↓
Task Definition: опис, ЯК запускати контейнер (образ, порти, CPU/RAM, змінні, IAM-роль, логи)
↓
Task: група контейнерів, запущених разом
↓
Service: тримає N tasks працюючими, масштабує
Усе це живе в ECS cluster. ECS запускає контейнери, EKS це Kubernetes (на діаграмі лише ECS).
Launch type
Fargate
  • serverless compute
  • AWS виділяє «комп'ютер» під контейнер
EC2
  • self-managed
  • роль інстанса має містити:
  • ecr:GetAuthorizationToken
  • ecr:BatchCheckLayerAvailability
  • ecr:GetDownloadUrlForLayer
  • ecr:BatchGetImage
Змінні й секрети
Task Execution Role (AmazonECSTaskExecutionRolePolicy) бере файли з S3 і значення з Secrets Manager чи SSM Parameter Store ще до старту.
Essential контейнери
Container A (essential)
  • впав: ECS зупиняє всю task
Container B (not essential)
  • впав: task продовжує працювати
Масштабування сервісу
ТипСуть
Target Trackingза цільовим значенням метрики CloudWatch
Step Scalingза конкретним CloudWatch alarm
Scheduledза розкладом, передбачувані зміни
Service Auto Scaling міняє кількість tasks за CPU, RAM чи Request count per Target. ASG масштабує лише EC2-інстанси.
Task Placement (EC2)
Strategies: ЯК обирати
  • binpack: щільно пакує, мінімізує витрати
  • spread: рівномірно по інстансах, AZ
  • least outstanding resources: де найменше вільного, але достатньо
Constraints: ДЕ можна
  • distinctInstance: різні EC2
  • memberOf: лише з потрібним ECS attribute
AWS Copilot CLI керує конфігами, деплоєм, генерує CloudFormation. Структура: Application, Environments (test/prod), Services (web/api/worker).
