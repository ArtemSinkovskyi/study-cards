В описі: що робить, коли використовувати й коли ні, що означає кожен параметр, чого не повертає. Мінімум 3-4 речення.
tool_choice
ЗначенняЩо робить
autoмодель сама вирішує (типово, коли є інструменти)
anyмусить викликати якийсь інструмент
toolмусить викликати саме названий
noneне викликає (типово, коли інструментів нема)
На Opus 5.5, Sonnet 5.5, Fable 5.1 і Mythos 5.1 значення any і tool дають 400, беріть auto зі strict. При any і tool модель не пише пояснення. Зміна tool_choice скидає кеш повідомлень.
Результати: три жорсткі правила (інакше 400)
1. tool_result одразу після повідомлення з tool_use
↓
2. У user-повідомленні блоки tool_result першими, текст після
↓
3. Кілька результатів одного ходу в одному повідомленні
Помилки
Інструмент упав
  • tool_result з is_error: true
  • не «failed», а «Rate limit exceeded. Retry after 60 seconds»
Щоб не було зовсім
  • strict: true
  • вхід відповідає схемі, ім'я завжди валідне
MCP
MCP (Model Context Protocol)
MCP-сервер дає набір інструментів
MCP connector: підключає віддалені сервери в Messages API (beta)
Connector підтримує
  • лише виклики інструментів
  • публічний HTTPS (Streamable HTTP, SSE)
Не підтримує
  • ресурси й промпти
  • локальний STDIO
  • приватну мережу
Асистент лише для читання
Denylist
  • вимкнути небезпечні
  • configs з enabled: false
Allowlist
  • default_config.enabled: false
  • увімкнути лише потрібні
Indirect prompt injection: чужий вміст тримайте всередині tool_result. У схему інструмента не кладіть персональні дані, вона кешується до 24 годин. Tool runner у SDK веде цикл сам, ручний цикл потрібен для схвалення людиною чи власного логування.
